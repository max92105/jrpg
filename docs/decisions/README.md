# Architecture decisions

One line per ADR: what was decided. Read the ADR itself before changing that area. New ADRs come from `/adr` (template: `_template.md`); add a line here when one is written.

| ADR | Area | Decided |
|---|---|---|
| [0001](0001-engine-free-architecture.md) | Architecture | `Jrpg.Core` holds every game rule with no rendering reference; `Jrpg.Game` (MonoGame) and `Jrpg.Editor` (WPF) are thin shells over it. |
| [0002](0002-content-schema-mapping.md) | Content | Content JSON loads straight into Core records; a Data DTO only where a file's format doesn't match the model, with the reason in that loader. |
| [0003](0003-equipment-ownership-model.md) | Items | Equipping takes the copy out of the inventory; unequipping puts it back. |
| [0004](0004-battle-command-flow.md) | Battle | One `Execute(BattleCommand)` per turn returns the ordered `BattleEvent`s; `EnemyTactics`, outside `BattleState`, chooses enemy commands. |
| [0005](0005-map-content-source-of-truth.md) | Content | *Superseded by 0011.* The WPF demo's `Assets/` and the converter were the source of truth for maps during the migration. |
| [0006](0006-map-event-flow.md) | Map events | `EventRun` steps through an event; swaps apply at once, dialogue, give-item and warp steps wait for `Continue()`; a "once" event is marked done when it starts. |
| [0007](0007-save-format-and-versioning.md) | Saves | Versioned JSON saves; a format change bumps `formatVersion` with a migration and a test on the old format; writes are atomic. |
| [0008](0008-game-shell-structure.md) | Game shell | Scenes return `SceneRequest`s that `GameFlow` applies through transition handlers; one `GameSession` at a time; the update path never touches the graphics device, so the flow runs headless in tests. |
| [0009](0009-art-location-and-asset-loading.md) | Art | Art lives in `content/art/<kind>/` as PNGs loaded at runtime through `TextureLibrary`; TTF fonts through FontStashSharp; `ArtReferenceCheck` checks references at startup. |
| [0010](0010-player-facing-text.md) | Text | Player-facing text lives in `content/text/ui.json`, with `{name}` placeholders; ids are constants in `Ui/MessageIds`, each checked by a test. |
| [0011](0011-content-after-the-converter.md) | Content | `content/` is the only source of truth: two files per map (settings and layout), catalogs at the content root, the editor writes through Data's `ContentWriter`. |
| [0012](0012-editor-architecture.md) | Editor | MVVM with `CommunityToolkit.Mvvm`; editing logic is headless (`MapDraft`, `IMapEdit`, `EditHistory`) and tested; content I/O only through Data. |
| [0013](0013-battle-presentation-and-playback.md) | Battle | The battle HUD reads live Core state (`Execute` at the moment of impact); the battle scene stacks over the map; playback is event-driven beats, exhaustive over `BattleEvent`. |
| [0014](0014-editing-shared-catalogs.md) | Editor | Catalogs (sheets, tiles, objects) are edited in one `CatalogDraft` read by every panel, saved with the map by Ctrl+S (`WriteMapCatalogs`, all three files or none) and undone by Ctrl+Z through a journal over map and catalog histories. |
| [0015](0015-npcs-on-maps.md) | Content | An NPC is an object drawn from a field sprite (`objects.json` `fieldSpriteFile`), placed with an Interact event; NPCs share a placeholder sprite until real art. |
| [0016](0016-intro-cinematics.md) | Map events | A character's intro is a map cutscene: an arrival-activated event (gated on the leader) of still steps (image, seconds, caption) and a voice step, run by `EventRun`, ending with a warp; skipping runs past presentation steps only. |
| [0017](0017-stats-come-from-the-class.md) | Party | A member's max HP, max MP, attack and defense are their class's at their level: `base + growth × (level − 1)` (`Party/ClassGrowth`); members hold no numbers, and saves stay level, XP, HP, MP and equipment. |
| [0018](0018-audio-files-and-playback.md) | Audio | Voices are 16-bit PCM WAV in `content/audio/voices/`, checked by exact name at startup and played with MonoGame's `SoundEffect`; scenes write a `VoiceChannel`, the host's `VoicePlayer` plays it; no device means silent, never a stop. |
| [0019](0019-class-battle-resources.md) | Battle | A class lists its resources in `classes.json` (max, start, gains on a closed set of triggers; optional backfire, dominance, max-from-speed and strain rules); skills spend, gain or require them; code never names a class or resource. |
| [0020](0020-skills-come-from-the-class.md) | Party | A member's skills are their class's (`classes.json` `skillIds`, in order); members hold no skills, and Data checks each skill uses only its class's resources; saves unchanged. |
| [0022](0022-mp-leaves-and-save-migrations.md) | Saving | MP leaves the game in four steps (skills, screens, saves, members); until the first release a save format change bumps `formatVersion` and refuses older saves, with no migration. |
| [0021](0021-status-effects.md) | Battle | Statuses are a closed `StatusKind` list in Core, granted by an effect with power and turns from content; they count down at the end of the holder's turns from the next one, refresh rather than stack, and end on a fall or with the battle. |
| [0023](0023-battle-formation.md) | Battle | The party's battle formation is a line starting from the active order (`Formation` in `BattleState`); distance is the difference in places, Move swaps with a neighbor and costs the turn, fallen allies keep their place, and the line resets after the battle. |
| [0024](0024-lasting-resources-and-rest.md) | Party | A resource marked `isLasting` keeps its amount on the member between battles (a `perBattleFought` gain, an optional `strain` on another resource's start), saved by id in format 3; `PartyMember.Rest()` restores full HP, revives and refills lasting resources. |
| [0025](0025-font-roles.md) | UI | Fonts have a role per folder: `content/art/fonts/` is the body font and its fallbacks, `content/art/fonts/titles/` the title serif (Cormorant Garamond SemiBold), which falls back to the body files; screens ask `FontLibrary.FontAt` or `TitleFontAt`, never a file. |
| [0026](0026-stat-model.md) | Stats | Five primaries (Power, Agility, Intelligence, Constitution, Will) from class growth and gear; derived stats convert at a percent per point with rates in `rules.json` `stats`, the battle's limits are constants beside their formulas, derived percents are held in tenths, and rolls draw only when uncertain. |
| [0027](0027-damage-types-and-resistances.md) | Stats | Eight damage types in Core (three physical, five magical); every hit has exactly one, from content; one resistance percent per type within −100..75 % replaces defense, a weakness is below 0, and a hit's damage is computed in a `long` and rounded down once. |
| [0028](0028-equipment-slots.md) | Items | Nine equipment slots as a Core enum (Weapon, OffHand, Head, Chest, Hands, Feet, Amulet, FirstRing, SecondRing); an item declares a kind, the ring kind fits both ring slots, every other kind its own; equipping names the slot, the off-hand holds no second weapon, and saves key worn items by slot in format 4. |
| [0029](0029-gear-pieces.md) | Items | A gear piece is a value: a base item, a rarity (Common, Magic, Rare; Unique reserved) and its rolled affixes in order, equal by content; the inventory keeps stacks for consumables and a list of pieces for gear, one row each with no cap; members wear pieces and keep their rolls wherever they move; saves keep each piece as its base id, rarity and affixes (id and value), format 5.
| [0030](0030-loot-rolls.md) | Loot | Rarity is a closed Core enum whose rolled tiers (Common, Magic, Rare) take a weight and an affix count range from `rules.json`; affixes are a content pool and drop tables a content file enemies name; loot rolls in `GameSession.FinishBattle` after the experience, with the session's random, drawing only when uncertain, and returns beside the rewards (`BattleSpoils`); only dropped gear rolls.
