# Architecture decisions

One line per ADR: what was decided. Read the ADR itself before changing that area. New ADRs come from `/adr` (template: `_template.md`); add a line here when one is written.

| ADR | Area | Decided |
|---|---|---|
| [0001](0001-engine-free-architecture.md) | Architecture | `Jrpg.Core` holds every game rule with no rendering reference; `Jrpg.Game` (MonoGame) and `Jrpg.Editor` (WPF) are thin shells over it. |
| [0002](0002-content-schema-mapping.md) | Content | Content JSON loads straight into Core records; a Data DTO only where a file's format doesn't match the model, with the reason in that loader. |
| [0003](0003-equipment-ownership-model.md) | Items | Equipping takes the copy out of the inventory; unequipping puts it back. |
| [0004](0004-battle-command-flow.md) | Battle | One `Execute(BattleCommand)` per turn returns the ordered `BattleEvent`s; `EnemyTactics`, outside `BattleState`, chooses enemy commands. |
| [0005](0005-map-content-source-of-truth.md) | Content | *Superseded by 0011.* The WPF demo's `Assets/` and the converter were the source of truth for maps during the migration. |
| [0006](0006-map-event-flow.md) | Map events | `EventRun` steps through an event; swaps apply at once, dialogue, give-item and warp steps wait for `Continue()`; a "once" event is marked done when it starts. |
| [0007](0007-save-format-and-versioning.md) | Saves | Versioned JSON saves; a format change bumps `formatVersion` with a migration and a test on the old format; writes are atomic. |
| [0008](0008-game-shell-structure.md) | Game shell | Scenes return `SceneRequest`s that `GameFlow` applies through transition handlers; one `GameSession` at a time; the update path never touches the graphics device, so the flow runs headless in tests. |
| [0009](0009-art-location-and-asset-loading.md) | Art | Art lives in `content/art/<kind>/` as PNGs loaded at runtime through `TextureLibrary`; TTF fonts through FontStashSharp; `ArtReferenceCheck` checks references at startup. |
| [0010](0010-player-facing-text.md) | Text | Player-facing text lives in `content/text/ui.json`, with `{name}` placeholders; ids are constants in `Ui/MessageIds`, each checked by a test. |
| [0011](0011-content-after-the-converter.md) | Content | `content/` is the only source of truth: two files per map (settings and layout), catalogs at the content root, the editor writes through Data's `ContentWriter`. |
| [0012](0012-editor-architecture.md) | Editor | MVVM with `CommunityToolkit.Mvvm`; editing logic is headless (`MapDraft`, `IMapEdit`, `EditHistory`) and tested; content I/O only through Data. |
| [0013](0013-battle-presentation-and-playback.md) | Battle | The battle HUD reads live Core state (`Execute` at the moment of impact, after a 0.7 s wind-up shown from the command, amended 2026-11-14); the battle scene stacks over the map; playback is event-driven beats, exhaustive over `BattleEvent`. |
| [0014](0014-editing-shared-catalogs.md) | Editor | Catalogs (sheets, tiles, objects) are edited in one `CatalogDraft` read by every panel, saved with the map by Ctrl+S (`WriteMapCatalogs`, all the catalog files or none) and undone by Ctrl+Z through a journal over map and catalog histories. |
| [0015](0015-npcs-on-maps.md) | Content | An NPC is an object drawn from a field sprite (`objects.json` `fieldSpriteFile`), placed with an Interact event; NPCs share a placeholder sprite until real art. |
| [0016](0016-intro-cinematics.md) | Map events | A character's intro is a map cutscene: an arrival-activated event (gated on the leader) of a voice step and a cinematic step (still steps until ADR 0046 replaced them), run by `EventRun`, ending with a warp; skipping runs past presentation steps only. |
| [0017](0017-stats-come-from-the-class.md) | Party | A member's max HP, max MP, attack and defense are their class's at their level: `base + growth × (level − 1)` (`Party/ClassGrowth`); members hold no numbers, and saves stay level, XP, HP, MP and equipment. |
| [0018](0018-audio-files-and-playback.md) | Audio | Voices are 16-bit PCM WAV in `content/audio/voices/`, checked by exact name at startup and played with MonoGame's `SoundEffect`; scenes write a `VoiceChannel`, the host's `VoicePlayer` plays it; no device means silent, never a stop. |
| [0019](0019-class-battle-resources.md) | Battle | A class lists its resources in `classes.json` (max, start, gains on a closed set of triggers; optional backfire, dominance, max-from-speed and strain rules); skills spend, gain or require them; code never names a class or resource. |
| [0020](0020-skills-come-from-the-class.md) | Party | A member's skills are their class's (`classes.json` `skillIds`, in order); members hold no skills, and Data checks each skill uses only its class's resources; saves unchanged. |
| [0022](0022-mp-leaves-and-save-migrations.md) | Saving | MP leaves the game in four steps (skills, screens, saves, members); until the first release a save format change bumps `formatVersion` and refuses older saves, with no migration. |
| [0021](0021-status-effects.md) | Battle | Statuses are a closed `StatusKind` list in Core, granted by an effect with power and turns from content; they count down at the end of the holder's turns from the next one, refresh rather than stack, and end on a fall or with the battle. |
| [0023](0023-battle-formation.md) | Battle | The party's battle formation is a line starting from the active order (`Formation` in `BattleState`); distance is the difference in places, Move swaps with a neighbor and costs the turn, fallen allies keep their place, and the line resets after the battle. |
| [0024](0024-lasting-resources-and-rest.md) | Party | A resource marked `isLasting` keeps its amount on the member between battles (a `perBattleFought` gain, an optional `strain` on another resource's start), saved by id in format 3; `PartyMember.Rest()` restores full HP, revives and refills lasting resources. |
| [0025](0025-font-roles.md) | UI | Fonts have a role per folder: `content/art/fonts/` is the body font and its fallbacks, `content/art/fonts/titles/` the title serif (Cormorant Garamond SemiBold), which falls back to the body files; screens ask `FontLibrary.FontAt` or `TitleFontAt`, never a file. |
| [0026](0026-stat-model.md) | Stats | Five primaries (Power, Agility, Intelligence, Constitution, Will) from class growth and gear; derived stats convert at a percent per point with rates in `rules.json` `stats`, the battle's limits are constants beside their formulas, derived percents are held in tenths, and rolls draw only when uncertain. |
| [0027](0027-damage-types-and-resistances.md) | Stats | Eight damage types in Core (three physical, five magical); every hit has exactly one, from content; one resistance percent per type within −100..75 % replaces defense, a weakness is below 0, and a hit's damage is computed in a `long` and rounded down once. |
| [0028](0028-equipment-slots.md) | Items | Nine equipment slots as a Core enum (Weapon, OffHand, Head, Chest, Hands, Feet, Amulet, FirstRing, SecondRing); an item declares a kind, the ring kind fits both ring slots, every other kind its own; equipping names the slot, the off-hand holds no second weapon, and saves key worn items by slot in format 4. |
| [0029](0029-gear-pieces.md) | Items | A gear piece is a value: a base item, a rarity (Common, Magic, Rare; Unique reserved) and its rolled affixes in order, equal by content; the inventory keeps stacks for consumables and a list of pieces for gear, one row each with no cap; members wear pieces and keep their rolls wherever they move; saves keep each piece as its base id, rarity and affixes (id and value), format 5.
| [0030](0030-loot-rolls.md) | Loot | Rarity is a closed Core enum whose rolled tiers (Common, Magic, Rare) take a weight and an affix count range from `rules.json`; affixes are a content pool and drop tables a content file enemies name; loot rolls in `GameSession.FinishBattle` after the experience, with the session's random, drawing only when uncertain, and returns beside the rewards (`BattleSpoils`); only dropped gear rolls.
| [0031](0031-gold-and-trade.md) | Trade | Gold is a capped purse whose overflow is lost; each enemy carries a gold range drawn once after the item drops; a price is the item's and each affix carries a gold value, so a piece is worth its base plus its affixes; shops list item ids and roll their gear once, kept in the save and rerolled after a leader level; selling pays a content share of the price, and every trade is a Core quote with its refusal. |
| [0032](0032-quest-log.md) | Quests | Quest progress is its own log in `WorldState`: each started quest's stage id and completion, changed only by the three quest steps with decision 388's rules for every state; stages are kept by id, so content inserting a stage moves nothing saved; story state that isn't a quest is a main-quest stage until flags get their own plan. |
| [0033](0033-quest-conditions.md) | Quests | A quest condition gates a whole event (`onlyWhenQuest`: the quest, one of five kinds, a stage for two of them) beside the leader and object gates; whether an event may start is one gate, `ActiveMap.CanStart`, asked by every trigger; the first event that may start wins, and content refuses one that would shadow its object's later events. |
| [0034](0034-enemy-tactics-and-boss-phases.md) | Battle | An enemy's tactics are a weighted list of actions (a skill, or the attack) with conditions from a closed set; one draw among the eligible, the attack with nothing eligible, the same draws without tactics; a boss's phases replace the list below an HP share, latched, entered at the end of `Execute`. |
| [0035](0035-music-and-sound-effects.md) | Audio | Extends 0018: music is chosen by the flow from its state and written to a channel after every update; effects are reported by scenes as values the flow copies after the scenes' update; WAV through `SoundEffect`, looped, paused and resumed per instance; a track is released when it leaves the mix, the two themes stay loaded. Amended 2026-11-05 and 2026-11-06: one folder per track, a track fades out before the next fades in, the title cycles its intro, loop and outro. |
| [0036](0036-third-party-placeholder-audio.md) | Audio | Placeholder sound effects come from freesound.org: a manifest names each file's source, author, license (CC0 first, CC-BY allowed, never NC or SA, never a rip), preview URL and conversion settings; a script fetches the public preview, converts it with ffmpeg (mono 44.1 kHz, lead-in trimmed, peak matched) and writes the credits; the WAVs are committed, ffmpeg is a per-PC tool. |
| [0037](0037-frozen-test-world.md) | Tests | Mechanism tests run on `tests/TestWorld/`, a frozen copy of the map side (maps, tiles, sheets, objects, new game, tilesheet images) laid over the live content into `test-world/` in each test output; repository tests load `content` and pin ids, never cells. |
| [0038](0038-art-sources-manifest.md) | Art | Every art file has a source in `content/art/art-sources.json` (sources: author, url, license as SPDX or `LicenseRef-`, placeholder flag; files: path and source), credits written by hand in `content/art/CREDITS.md`, both kept in step by a Data test reading the repository folder; CC0, CC-BY, OFL and bought-pack licenses allowed, never NC or SA; unrecorded or generated only on placeholders. |
| [0039](0039-animated-tiles.md) | Maps | A tile may carry `animation` (`frameCount` from 2, rightward from its own cell on its row; `frameMilliseconds` from 1, one time for every frame); Core's `TileAnimation.FrameAt` turns an elapsed time into a frame, the game's time is the map view's, the editor's the render tick's; canopies and the editor's map show the first frame; a Tiled `.tsx` of another shape is refused. |
| [0050](0050-unexpected-errors-in-the-editor.md) | Editor | An exception nothing caught on the editor's UI thread is written to a report file and asked about in a box, and the editor stays open with its draft; the same error again is counted, never asked or written twice; closing goes through the usual close question; no autosave. |
| [0054](0054-field-sprite-facing-sequences-and-mirrors.md) | Sprites | A field sprite facing shows its row, a sequence of cells picked anywhere on its sheet in order (repeats allowed), or the mirror of another facing flipped left to right; an optional `walk.sequences` overrides the rows, which every record keeps, so old records load unchanged; a cell's members are both required; Core gives a facing's frame as a `SpriteFrame`; amends ADR 0043. |
| [0055](0055-statuses-as-content-records.md) | Battle | A status is a record in `statuses.json` built from a closed list of parts (tick damage or heal, skip a turn, draw attacks, resistance, damage taken, later damage dealt and stat changes), one amount each; a holder keeps one per family; a grant names a record with its turns and a chance; records resolve at load; amends ADR 0021. |
| [0056](0056-damage-tiers-as-an-effects-catalog.md) | Battle | Damage tiers are named records in `effects.json` (`fire_1`, `heal_2`: a kind, a damage type and `perPower`); a skill's effect names one as `tier`, resolved at load by `CatalogReferenceConverter<T>`; a tiered amount is the user's Power times `perPower` times 1 plus the damage modifiers' sum, held at `DamageFormula.MaxPower`; Power's percent no longer raises a tiered effect; enemies get a content power; items keep a flat power. |
| [0057](0057-enemy-rules-triggers-reactions-and-targets.md) | Battle | An enemy's action becomes a rule: *when* (one trigger from a closed list, reactions to being hit, critically hit or hit on a weakness included), *use* (a skill or the attack), *on* (a target rule from a closed list, or automatic as today), a weight, and optional priority (the first eligible priority rule wins before any draw) and once per battle; reactions are remembered at the end of `Execute` and answered on the enemy's next turn, never out of turn; eligibility never draws; amends ADR 0034. |
| [0058](0058-unique-items-as-records-with-fixed-affixes.md) | Items | A unique is its own item record in `items.json` (`isUnique`, equipment, `fixedAffixes` naming pool affixes with a value each, free within the bonus bound on the affix's side of zero), its piece always built from the record (a drop, a stock, a gift, a starting item, a restored save), dropped by its id only (a base never rolls Unique), owned in any number of copies, never rerolled at the Forge, priced as its base plus its affixes' gold values with one sale share for every item; no save format change; decisions 681, 866 and 875 are defaults to confirm; amends ADR 0029. |
| [0059](0059-animated-battle-backgrounds-as-grid-sheets.md) | Battle | An animated battle background is a grid sheet PNG of reduced frames scaled up by the game, its frame size, count and time a record in `animated-backgrounds.json`; the editor makes it from a GIF and plays it before writing; a 24-frame loop is at most 960 x 540. |
| [0049](0049-battle-screen-effects-as-additive-sprites.md) | Battle | The battle draws its impact light (the warm flash, the white wash, the floor glow, the halo) and its color fringes with `SpriteBatch` alone, in additive batches over textures baked once; the fringes are the impact strip's frame and the white silhouettes as red, green and blue copies shifted apart, before the numbers, so the HUD stays clean; no shader, no post-process, no render target change. |
| [0048](0048-battle-effect-strips-as-records.md) | Battle | An effect strip's pace is a record in `effect-strips.json`, by the strip's file name: its frame time, the frame its hit lands on and the swing it plays first; a strip it doesn't list plays at 80 ms a frame, its hit on frame 0, no swing; edited in a Database window. Amended 2026-11-15: a skill's or item's own strip. |
| [0047](0047-animated-battle-sprites.md) | Battle | An animated enemy is a PNG strip the editor composes from a GIF at import, scaled to a battle height (default 128 px); the enemy record declares its loop as `idleAnimation` (ADR 0039's frame count and one frame time, the GIF's most common delay), absent for a still sprite; the game stays PNG-only. |
| [0046](0046-cinematics-as-content-records.md) | Cinematics | A cinematic is a record in `cinematics.json` (an optional track, its stills in order with seconds, subtitle, voice, zoom and an optional focus point (amended 2026-11-15)), edited in a Database window and played by one `cinematic` event step that keeps the scripting around it; a still names its picture with its cinematic's folder; amends ADR 0016 (presentation) and ADR 0009 (folder in the name). |
| [0045](0045-database-editors.md) | Editor | Each catalog gets a hand-written editor window whose problem line is its own checks for what Data can't see and then the loader's own message (`CatalogProblems`), rows over a Core enum generated from the enum; a window removes only the records added in its session, an id is typed while new and fixed once the draft holds it, a window's session is one undo step (a window opened over another applies its own step, and the outer one reads the draft again, decision 602); a file the editor takes over is relaid once through the writer; the first balancing tool is a read-only side-by-side table. |
| [0044](0044-npc-facing-and-cutscene-movement.md) | Exploration | An NPC faces, first rule that applies: its walk's step, the player while an event of its own runs (the shop or Forge it opened included), its last walk's facing this visit, its placed facing (down when absent); a `moveNpc` step walks a placed NPC along a path of one-cell steps at the player's speed while the event waits, through walls and the player, its position kept in the active map for the visit only; nothing saved (amends ADR 0015's decisions 127, 128). |
| [0043](0043-field-sprite-sheets-as-content.md) | Sprites | Every field sprite image has a record in `field-sprites.json`, keyed by file name in exact case: its frame size, a whole-number draw scale with the feet line on the cell's bottom edge, the row each facing reads and a walk in ADR 0039's shape from column 0; an object or new game naming a sprite without a record is refused; the player's sheet is one record with today's numbers (amends ADR 0015). |
| [0042](0042-renaming-map-ids-before-the-first-release.md) | Maps | Until the first release the editor renames a map id at once with every content reference (its two files, every warp into it, the new game's start), refused while anything is unsaved, the undo histories starting afresh; a save naming the old id is repaired as for a removed map; from the first release a rename needs a rename table. |
| [0041](0041-placed-object-draw-order.md) | Maps | One draw order built in Core (`MapDrawOrder`), read by the game, the editor's drawing and its hit test; a sprite sorts by the layer it comes from, a canopy by its object's, so a higher layer draws over a lower one, canopies included; a canopy still draws over the player and so over every body under the canopy layer. |
| [0040](0040-object-tile-levels.md) | Maps | An object tile carries `level` (-7 to 7 since its amendment, 0 the base, left out of `objects.json` while 0); one tile per cell and level, listed bottom level first, refused otherwise naming the tile; every drawer draws the list in order and the canopy bake composes each tile over the one under it; content files have no version, saves are untouched. |
