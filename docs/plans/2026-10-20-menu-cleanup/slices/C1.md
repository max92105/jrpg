# C1. `PartyState.ReserveMembers`

Part of [the menu cleanup plan](../README.md). Design: [design.md](../design.md), "Core changes" and key decision 4.

- **C1. `PartyState.ReserveMembers`** (Core + Game, about 90 lines; decision 108)
  - **Goal:** Core lists the reserve, in recruitment order (decision 108). The Party page and `MemberOrder` read it instead of computing "members not active" themselves (P4-1 follow-up). Nothing changes on screen.
  - **Changes (Core):** `Party/PartyState` gains `public IReadOnlyList<PartyMember> ReserveMembers`: recruited members not in the active party, in recruitment order.
    - It is a private list, rebuilt in the constructor and after a successful `TryAddToActive` or `TryMoveToReserve`, so reading it never allocates.
    - The class summary mentions the reserve.
  - **Changes (Game):**
    - `Menus/PartyPage` drops `_reserve`. `MembersIn(ReserveColumn)` returns `_party.ReserveMembers`.
    - `Menus/MemberOrder.ActiveThenReserve` returns `[.. party.ActiveMembers, .. party.ReserveMembers]`.
  - **Tests (Core, `PartyStateTests`):**
    - `ReserveMembers_NewParty_AreTheInactiveRecruitsInRecruitOrder`;
    - `ReserveMembers_AfterTryAddToActive_LeavesOutTheJoiner`;
    - `ReserveMembers_AfterTryMoveToReserve_PutsTheMemberBackInRecruitOrder`;
    - `ReserveMembers_AfterRefusedTryAddToActive_Unchanged` (party full).
  - **Tests (Game):** `PartyPageTests` and `StatusPageTests` pass unchanged. `PartyPageTests`' `Members.Except(ActiveMembers)` may read `ReserveMembers` instead; the assertions stay the same.
