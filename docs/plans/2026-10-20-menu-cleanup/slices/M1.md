# M1. Entering a page rebuilds it from Core and starts on the first entry

Part of [the menu cleanup plan](../README.md). Design: [design.md](../design.md), "What exists" (menu pages) and key decision 2.

- **M1. Entering a page rebuilds it from Core and starts on the first entry** (Game, about 260 lines; decision 109)
  - **Goal:** each time Confirm enters a page from its tab, the page rebuilds what it shows from Core, puts its cursor on the first entry and clears any notice (decision 109). This closes the P4-1 known gap; Status had the same gap.
  - **Changes:**
    - `Menus/IMenuPage` gains `void Open();`. Doc: "Called each time the player enters the page from its tab: rebuilds what it shows from Core and starts on the first entry." Same verb as `ISaveFilesPage.Open`.
    - `Menus/GameMenuScene.UpdateTabs`: on Confirm, `_pages[_tabs.Selected].Open()`, then `_isInPage = true`.
    - Per page. Cursor fields stay `readonly` and use `Select(0)`; nothing restores the previous member:
      - `PartyPage.Open`: `Notice = null`, column Active, row 0, `ShowParty()`.
      - `StatusPage.Open` and `EquipmentPage.Open`:
        - `Members` gets a private setter and is rebuilt with `MemberOrder.ActiveThenReserve`. Recruits don't change in the menu, so the member cursor's count holds;
        - `_cursor` / `_memberCursor.Select(0)`;
        - the sheet is rebuilt;
        - Equipment also selects row 0 and clears its notice.
        
        The constructors call the same private method.
      - `InventoryPage.Open`: `_notice = null`, `_categoryCursor.Select(0)`, `ShowRowsFrom(0)`.
      - `OptionsPage.Open` and `SystemPage.Open`: `_cursor.Select(0)`. Options reads `PlayerSettings` when drawing, and System's save files are read by their own `Open()`, so there's nothing else to rebuild.
    - **Read seams for tests** (`internal`, read-only):
      - `PartyPage.CardOf(PartyMember member)` returns the member's formatted card (`PartyMemberCardView.Card`, from U4 on `Ui/MemberCardView.Card`);
      - `StatusPage.ShownStats` returns the sheet's stat texts (HP, MP, Attack, Defense).
  - **Tests (Game):**
    - `GameMenuSceneTests`:
      - `Update_ConfirmOnTab_OpensThatPage`, with a test double `Menus/CountingMenuPage` in the test project (counts `Open` calls) as the only page;
      - `Update_ConfirmOnTabAgainAfterCancel_OpensThePageAgain` (count 2).
    - `PartyPageTests`:
      - `Open_AfterHpChanged_CardShowsTheNewHp`: build the page, `Vitals.TakeDamage` on the leader through the session, then `Open()`. `CardOf(leader).Hp.Bar.Fraction` is the new HP over max. This is format-independent, so U3 leaves it alone;
      - `Open_AfterMovingTheCursor_StartsOnTheLeader`: Right, then `Open()`. `Selected` is the leader.
    - `StatusPageTests`:
      - `Open_AfterHpChanged_ShowsTheNewHp`: `ShownStats[0]` is `"{hp} / {max}"`, already decision 110's format;
      - `Open_AfterMemberJoinedElsewhere_ListsThemAmongTheActive`;
      - `Open_AfterMovingToAnotherMember_ShowsTheFirst`.
    - `EquipmentPageTests.Open_AfterMemberJoinedElsewhere_ListsThemAmongTheActive`.
    - `InventoryPageTests`:
      - `Open_AfterLastCopyTakenElsewhere_NoLongerListsIt` (`Inventory.TryRemove` for an item's whole stack);
      - `Open_ClearsTheLastUseNotice`;
      - `Open_AfterChangingCategory_ShowsAll`.
    - `OptionsPageTests.Open_AfterMovingDown_SelectsFullScreen`.
  - **Verify by hand:**
    - [ ] Hurt a member (in a save), use a potion on Inventory, then go to Party and Status without closing the menu. The new HP shows on both.
    - [ ] Reorder on Party, then go to Status and Equipment. They start on the leader and follow the new order.
    - [ ] Equip the iron sword, then go to Inventory. Its count dropped, and the list starts on All, row 1.
