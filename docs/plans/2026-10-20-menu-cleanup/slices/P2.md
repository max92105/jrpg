# P2. The party page views

Part of [the menu cleanup plan](../README.md). Design: [design.md](../design.md), key decision 8.

- **P2. The party page views** (Game, about 250 lines, mostly moved)
  - **Goal:** the Party page's drawing moves to two views, and the page keeps input, its sub-states and commands to Core, at about 180 lines. Nothing changes on screen. The cards are already drawn through `Ui/MemberCardView` (U4), so this slice only moves the code around them.
  - **New types (Game):**
    - `Menus/PartyColumnsView`, `internal sealed`. It draws the Party page's two columns (legacy `PartyView`): the section titles, the active count, each member's card, the moving member's outline, and the notice.
      - `public PartyColumnsView(ScreenText text, UiTextures ui, ContentCatalog catalog)`. It owns the `MemberCardView`, the two `SectionTitle`s and the fonts.
      - `public void Draw(SpriteBatch batch, TextureLibrary textures, Place place, float opacity)`.
      - `public readonly record struct Place(PartyColumns Columns, Rectangle Area, PartyCursor Cursor, PartyMember? Moving)`. `PartyColumns` is the page's formatted state: cards by member, the count, the notice.
      - `public Rectangle CardArea(Rectangle area, bool onReserve, int row)`, so the page can place the action choice over a card.
    - `Menus/PartyColumns`: `internal sealed record PartyColumns(IReadOnlyDictionary<PartyMember, MemberCardView.Card> Cards, MeasuredText Count, string? Notice)`. It is the Party page's text as last formatted, rebuilt by `ShowParty` and on each notice. M1's `CardOf` seam reads `Cards`.
    - `Menus/PartyActionChoiceView`, `internal sealed`. It draws the action choice as a small glass panel over a card's right (legacy `GlassPanelStyle`, `ListRow` rows), with "To reserve" greyed when Core refuses it (C2).
      - `public PartyActionChoiceView(ScreenText text, UiTextures ui)`. It owns the action labels.
      - `public void Draw(SpriteBatch batch, TextureLibrary textures, Place place)`.
      - `Place(ListCursor Choice, Rectangle Card, bool IsToReserveAllowed)`. It draws at full opacity, as today, since the choice opens only after the fade.
  - **Changes (`PartyPage`):**
    - The layout constants, `DrawCards`, `DrawMovingOutline` and `DrawActionChoice` go, with the count and notice drawing.
    - `Draw` is two calls.
    - `_actions` labels move to `PartyActionChoiceView`. The page keeps the action count and the `ChangeOrderEntry` index.
  - **Tests:** none new; this slice only moves drawing code. `PartyPageTests` and `PartyCursorTests` pass unchanged.
