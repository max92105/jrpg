# E12b. A new object from the rectangle

Part of [the editor plan](../README.md). Design: [design.md](../design.md), "Folder dependencies" (`Shell` alone connects `Tiles` to `Objects`), "Legacy mapping" (`NewObjectWindow`, `TileGroupObjectCreator`); decision 124. Builds on E12a (the rectangle) and E9 (`CatalogDraft.SetObject`, the shapes window).

- **E12b. A new object from the rectangle** (Editor, about 260 lines)
  - **Goal:**
    - Objects > **New object from selection...** (enabled with a rectangle chosen) asks for an **Id** and a **Category** (an editable list of the categories in use today: Chests, General, House; a new one can be typed). OK is disabled with the reason while the id is empty, taken, or not lowercase letters, digits and `_` (as every content id is), or the category is empty.
    - On OK: cells of the rectangle that aren't tiles yet become tiles (E3d's rule, decision 114); the object is made with the rectangle's size, one tile per cell, no collision outline and no zones; every cell is kept, even a fully transparent one (decision 124: the editor doesn't read pixels). It joins the catalog draft as one step ("Unsaved changes"). Ctrl+Z removes it, unless a map places it (refused, naming the map; E4b's rule, extended to objects).
    - The editor then switches to the Objects tab with the new object chosen, and opens its shapes window (E9-E11b) so the outline and zones are drawn right away (decision 124). Cancelling the shapes window keeps the object, without shapes.
  - **New types:**
    - `Objects/ObjectIds` (static): what is wrong with a typed object id, if anything (empty, taken, characters). Also used by N3.
    - `Objects/ObjectFromCells` (static, pure): the object definition a rectangle of sheet cells makes. `Build(string id, string category, SheetCellRectangle cells, Func<SheetCell, int> tileIdOf)`.
    - `Objects/NewObjectViewModel` (`ObservableObject`): the id and category typed for a new object, and what stops them being used.
      - `NewObjectViewModel(IReadOnlyCollection<string> takenIds, IReadOnlyList<string> categories, SheetCellRectangle cells)`.
      - `Id`, `Category` (observable), `Categories` (distinct, sorted), `SizeText` ("3 x 4 cells"), `IdProblem`, `CategoryProblem`.
    - `Objects/NewObjectWindow` (XAML + code-behind, no rules): the two fields, their problems, OK and Cancel, as `NewMapWindow`.
  - **Changes:**
    - `Catalogs/CatalogUsage.UsersOfObject(ContentCatalog catalog, string objectId, MapLayout? openLayout)`: the maps placing it; the undo refusal covers objects.
    - `Shell/MainViewModel`:
      - `StartNewObject()`: a `NewObjectViewModel` for the chosen rectangle, or null without one;
      - `CreateObject(NewObjectViewModel newObject)`: adds the missing tiles (`CatalogDraft.TileAt`, `AddTile`), `SetObject(ObjectFromCells.Build(...))`, chooses it in `Placing.Browser`, sets `Mode` to Objects.
    - `Shell/MainWindow`: the menu entry, the dialog, then E9's shapes window through `Placing.StartEditingShapes()`.
  - **Existing tests this breaks:** none.
  - **Tests:**
    - `ObjectIdsTests`: `ProblemOf_IdTaken_SaysSo`, `ProblemOf_CapitalsOrSpaces_SaysWhichCharactersAreAllowed`, `ProblemOf_SnakeCaseId_IsNull`.
    - `ObjectFromCellsTests`: `Build_ThreeByTwoCells_PlacesOneTilePerCell`, `Build_AnyRectangle_HasNoOutlineAndNoZones`.
    - `NewObjectViewModelTests`: `CategoryProblem_Empty_SaysSo`, `Categories_RepositoryObjects_AreDistinctAndSorted`.
    - `CatalogUsageTests`: `UsersOfObject_PlacedOnOpenMap_ListsIt`.
    - `MainViewModelTests`:
      - `CreateObject_CellsNotTilesYet_AddsTilesAndTheObjectThenChoosesIt` (the draft passes `WriteMapCatalogs`' validation: saved into a temporary content copy and loaded back);
      - `Undo_NewObjectPlacedOnASavedMap_RefusesAndNamesTheMap`.
