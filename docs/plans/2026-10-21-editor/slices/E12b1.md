Part of [the editor plan](../README.md). Nothing is visible until E12b2.

- **E12b1. A new object from the rectangle: the rules and the catalog step** (Editor, about 290 lines)
  - **Goal:**
    - A new object's **Id** and **Category** are checked: the id must not be empty or taken and must be lowercase letters, digits and `_` (as every content id is); the category must not be empty. The categories offered are the ones in use today (Chests, General, House), and a new one can be typed.
    - Creating it: cells of the rectangle that aren't tiles yet become tiles (E3d's rule, decision 114); the object is made with the rectangle's size, one tile per cell, no collision outline and no zones; every cell is kept, even a fully transparent one (decision 124: the editor doesn't read pixels). It joins the catalog draft as one step ("Unsaved changes") and is chosen in the Objects panel, in Objects mode. Ctrl+Z removes it, unless a map places it (refused, naming the map; E4b's rule, extended to objects).
  - **New types:**
    - `Objects/ObjectIds` (static): what is wrong with a typed object id, if anything (empty, taken, characters). Also used by N3.
    - `Objects/ObjectFromCells` (static, pure): the object definition a rectangle of sheet cells makes. `Build(string id, string category, SheetCellRectangle cells, Func<SheetCell, int> tileIdOf)`.
    - `Objects/NewObjectViewModel` (`ObservableObject`): the id and category typed for a new object, and what stops them being used.
      - `NewObjectViewModel(IReadOnlyCollection<string> takenIds, IReadOnlyList<string> categories, SheetCellRectangle cells)`.
      - `Id`, `Category` (observable), `Categories` (distinct, sorted), `SizeText` ("3 x 4 cells"), `IdProblem`, `CategoryProblem`.
  - **Changes:**
    - `Catalogs/CatalogUsage.UsersOfObject(ContentCatalog catalog, string objectId, MapLayout? openLayout)`: the maps placing it; `CatalogDraft.ObjectsRemovedByUndo()`; the undo refusal covers objects.
    - `Shell/MainViewModel`:
      - `StartNewObject()`: a `NewObjectViewModel` for the chosen rectangle, or null without one;
      - `CreateObject(NewObjectViewModel newObject)`: adds the missing tiles (`CatalogDraft.TileAt`, `AddTile`), `SetObject(ObjectFromCells.Build(...))`, chooses it in `Placing.Browser`, sets `Mode` to Objects.
  - **Tests:**
    - `ObjectIdsTests`: `ProblemOf_IdTaken_SaysSo`, `ProblemOf_CharactersOutsideSnakeCase_SaysWhichAreAllowed`, `ProblemOf_SnakeCaseId_IsNull`.
    - `ObjectFromCellsTests`: `Build_ThreeByTwoCells_PlacesOneTilePerCell`, `Build_AnyRectangle_HasNoOutlineAndNoZones`.
    - `NewObjectViewModelTests`: `CategoryProblem_Empty_SaysSo`, `Categories_RepositoryObjects_AreDistinctAndSorted`.
    - `CatalogUsageTests`: `UsersOfObject_PlacedOnOpenMap_ListsIt`.
    - `MainViewModelTests`:
      - `CreateObject_CellsNotTilesYet_AddsTilesAndTheObjectThenChoosesIt` (the draft passes `WriteMapCatalogs`' validation: saved into a temporary content copy and loaded back);
      - `Undo_NewObjectPlacedOnASavedMap_RefusesAndNamesTheMap`.
  - **Verify by hand:** nothing to see until E12b2.

Review: a test that a taken id makes nothing (`CreateObject_IdTaken_ReturnsFalseAndKeepsTheObject`).
