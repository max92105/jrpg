# E12c. Selecting sheet cells by dragging, and making an object from them there

Part of [the editor plan](../README.md). Added after E13c from the developer's feedback (2026-10-22): making an object from several sheet cells "doesn't seem to be the case right now; it was in the legacy one". E12a and E12b built it, but behind Shift + drag, with no outline while dragging and the command only in the Objects menu and tool bar.

- **E12c. Selecting sheet cells by dragging, and making an object from them there** (Editor, about 100 lines)
  - **Goal:**
    - A plain drag over the sheet in the Tiles panel selects the rectangle of cells it covers, as legacy did; Shift + drag still works. A plain click still chooses one cell (a click on the margin keeps the choice).
    - The dashed rectangle follows the mouse while dragging.
    - Under the sheet, a **New object from selection...** button shows while several cells are selected, and the line under the sheet says what the selection does: "3 x 4 cells selected: the brush paints the top-left one; New object from selection makes an object of them."
    - Mark blocked mode is unchanged (a click flips a cell).
  - **Changes:**
    - `Tiles/TileBrowserView.xaml.cs`: a left press remembers where it started and chooses the cell under it; once the mouse moves past the system drag distance, every move selects the rectangle (`SelectCellsBetween`), and the release keeps it.
    - `Tiles/TileBrowserViewModel.ChoiceText`: the selection line above.
    - `Shell/MainWindow.xaml`: the button in the Tiles tab, shown by `CanStartNewObject`, using the menu's handler.
    - Controls help (F1): drag (or Shift + drag) to select cells; the button.
  - **Tests:** `TileBrowserViewModelTests`: the selection line (the existing `SelectCellsBetween_TwoCells_ChoosesTheRectangleAndItsTopLeftCell` pins the new text).
  - **Verify by hand:**
    - [ ] Drag over 3 x 2 cells of a sheet: the dashed rectangle follows the mouse; on release the line says "3 x 2 cells selected" and the button shows; click it: the New object dialog opens; create: the shapes window opens.
    - [ ] A plain click still chooses one cell and hides the button; painting still uses the top-left cell of a selection.
- **Done, with deviations:** as planned. Checked live: a plain drag over the city sheet selected 3 x 3 cells with the dashed rectangle following the mouse, and the line and the button showed under the sheet. The line names the button rather than saying where it is; the drag flag resets with the press when the capture ends (review). The line under the sheet now wraps (it was cut off in the 420 px panel). The checks pass with the repository content; the developer's uncommitted `forest.json`/`tiles.json` edits fail three content-pinning tests (a new layer, new tiles), to update when those edits are committed.
