# E13a. Layout: splitters and tool bars per mode

Part of [the editor plan](../README.md). Design: [design.md](../design.md), "Tunables" (panel sizes); decision 121. Split up front (review): the layout first, the dark theme in E13b.

- **E13a. Layout: splitters and tool bars per mode** (Editor, about 150 lines, almost all XAML)
  - **Goal:**
    - **Tool bars follow the editing mode** (legacy `ToolBarTray` bands): one band always shown (Save, Undo, Redo, the layer box, Grid, Dim other layers, Show collision), and one per mode: Tiles (brush, rectangle, fill, sizes, eyedropper, fill and clear layer, Mark blocked), Objects (Edit shapes, New object from selection, New NPC), Events (none today, so no band).
    - **Resizable panels:** the map list (200 px, min 140) and the side panel (420 px, min 300) have splitters; the map view takes the rest.
    - Nothing else changes: same commands, same keys, same order within each band.
  - **Changes:**
    - `Shell/MainWindow.xaml`: a `ToolBarTray` with the shared band and the mode bands, shown by `DataTrigger`s on `Mode` (no code); the outer layout becomes a `Grid` with two `GridSplitter`s and the panel sizes above (named in one place, the window's resources).
  - **Tests:** none new: layout only, and the editor tests run without a window. Existing tests pass unchanged. Before and after screenshots in the slice's "Done" note.
  - **Verify by hand:**
    - [ ] Switch tabs: the Tiles band shows only in Tiles mode, the Objects band only in Objects mode; the shared band never moves.
    - [ ] Drag both splitters: they stop at their minimum; the map view resizes and Fit (Ctrl+0) uses the new size.
    - [ ] Every earlier hand check that names a toolbar button still finds it (in its mode's band, or the menu).
    - [ ] At 125 % and 150 % Windows scaling: no clipped labels, no empty strip at the top (E1 still holds).
