# E13b. Dark theme

Part of [the editor plan](../README.md). Design: [design.md](../design.md), "Tunables" (editor theme), "Extension points" (a look value); decision 121. Last of the behavior-free slices: it restyles windows whose commands and layout are settled (E13a).

- **E13b. Dark theme** (Editor, about 230 lines, almost all XAML)
  - **Goal (decision 121: a dark theme like the legacy MapEditor):**
    - Every window of the editor (main window, new map, map settings, cell event, object events, controls help, object shapes, new object, new NPC) uses one dark theme: window `#111111`, panels `#181818`, viewport and status bar `#202020`, borders `#333333`, text `#DDDDDD`, the status message `#88CC88`, problems and errors `#FF6B6B`, warnings `#E0A040`.
    - Nothing else changes: same commands, keys and layout.
  - **New types:**
    - `Shell/EditorTheme.xaml` (resource dictionary): the theme's brushes, named by role (`WindowBackgroundBrush`, `PanelBackgroundBrush`, `ViewportBackgroundBrush`, `BorderBrush`, `TextBrush`, `MutedTextBrush`, `StatusTextBrush`, `ProblemTextBrush`, `WarningTextBrush`), and the implicit styles that use them (`Menu`, `MenuItem`, `ToolBar`, `TabControl`, `TabItem`, `ListBox`, `ListBoxItem`, `TextBox`, `Button`, `CheckBox`, `RadioButton`, `Expander`, `StatusBar`, `GridSplitter`) plus an `EditorWindow` style every window sets (WPF doesn't apply implicit styles to `Window` subclasses).
  - **Changes:**
    - `Hosting/App.xaml`: merges `Shell/EditorTheme.xaml` (`Hosting` already depends on `Shell`).
    - Every view: inline colors move to theme keys (`DarkRed` -> `ProblemTextBrush` in `NewMapWindow`, `MapSettingsWindow`, `CellEventWindow`, `ObjectEventsWindow`, `EventStepEditor`; `Gray` -> `MutedTextBrush`; `DarkOrange` -> `WarningTextBrush`; `#202020` in `MainWindow`, `TileBrowserView`, `ObjectBrowserView` -> `ViewportBackgroundBrush`). Drawing colors (map marks, overlay, handles) stay named constants in their drawing classes.
  - **Tests:** none new: look only. Existing tests pass unchanged. Before and after screenshots of each window in the slice's "Done" note.
  - **Known risk:** WPF's default templates ignore `Background` on `ComboBox` drop-downs and scroll bars under the Windows 10/11 theme, so they stay light unless re-templated. If dark templates for them push the slice past about 300 lines, they move to a slice of their own right after; the rest of the theme lands here.
  - **Verify by hand:**
    - [ ] Open every window listed above: text readable on dark, problems red, warnings amber, the status message green; no light patch except the known ComboBox and scroll bar gap if split out.
    - [ ] Hover, focus and disabled states of buttons, check boxes and menu entries are visible.
- **Done, with deviations:** split as the slice's "Known risk" planned: combo boxes, scroll bars and the tool bars' overflow buttons keep their light Windows templates and move to [E13c](E13c.md). Until then a combo box outside a tool bar has dark text on its light box, and its drop-down rows light text on dark. The theme also redefines the system colors the default templates read (menus, lists, drop-downs, selection), and re-templates `Button` (and the tool bar's button style) and `TabItem`, whose defaults turn light on hover or when selected. The tool bar bands' styles are based on the theme's. `TileBrowserView`'s `DarkGoldenrod`/`Firebrick` went to the warning/problem brushes too. Screenshot checked: the main window only (dialogs need a session); the hand checks remain.
- **Review follow-up:** the tool bar combo box style override went, so tool bar combo boxes keep the Windows tool bar look reading the theme's system colors (dark; a screenshot shows only their drop-down end light, now in E13c). The open menus' light frame and separators (hard-coded by Windows) joined E13c's scope. The default button (OK, Create) has the selection border; the interim combo text uses its own `OnLightTextBrush`.
