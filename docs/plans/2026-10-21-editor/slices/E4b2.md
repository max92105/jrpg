# E4b2. An undo that would remove a used tile is refused

Part of [the editor plan](../README.md). Design: [design.md](../design.md), "Risks" (undo across two histories); decision 117; ADR 0014. Split from E4b at step 2; builds on [E4b1](E4b1.md)'s journal and catalog history.

- **E4b2. An undo that would remove a used tile is refused** (Editor, about 150 lines)
  - **Goal:**
    - An undo that would remove a tile still used, by the open map (unsaved content included), a saved map or an object, is refused; nothing changes, and the status line names the user: "Can't undo: tile 284 is used on map forest."
    - The check is the one place later slices extend: a sheet's tiles (E6), objects placed on maps (E12b).
  - **New types:**
    - `Catalogs/CatalogUsage` (static, pure): which maps and objects use a tile, in a catalog plus the open map's unsaved layout.
  - **Changes:**
    - `Catalogs/CatalogDraft`: the tiles the next undo would remove (the undo's result compared with `Current`), so the shell can check them before undoing.
    - `Shell/MainViewModel.Undo`: before a catalog undo, `CatalogUsage` checks those tiles; a refusal shows its line in the status bar and leaves both histories and the journal as they were.
  - **Tests:**
    - `CatalogUsageTests`: `UsersOfTile_TileOnSavedMapAndOpenMap_ListsBoth`, `UsersOfTile_UnusedTile_IsEmpty`.
    - `MainViewModelTests`: `Undo_NewBlockedTileUsedOnAnotherMap_RefusesAndNamesTheMap`.
  - **Verify by hand:**
    - [ ] Mark a new cell blocked, paint it, save, open another map, Ctrl+Z: refused, naming the first map.
