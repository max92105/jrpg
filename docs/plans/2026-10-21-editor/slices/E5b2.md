# E5b2. The Cut panel: columns and rows

Part of [the editor plan](../README.md). Design: [design.md](../design.md), "Key decisions" 5; decision 115. Split from E5b (developer, 2026-10-21); builds on [E5b1](E5b1.md)'s set-up, guess and id. Set-up and cut are one step (review): **Set up** opens the Cut panel pre-filled with the guessed cut, and **Apply** creates the sheet.

- **E5b2. The Cut panel: columns and rows** (Editor, about 260 lines)
  - **Goal:**
    - **Set up** (and Tiles > Set up sheet) now opens the **Cut** panel under the sheet, pre-filled with E5b1's guessed cut turned into columns and rows.
    - The panel shows the sheet's id, then **Columns** and **Rows** (as asked), **Margin** and **Spacing**, then, read-only, the tile size they give ("48 x 48 px") and the count ("8 x 16 = 128 cells") (decision 115: no tile-size input).
    - Editing a field redraws the grid over the image at once (a preview; the catalog doesn't change yet).
    - A cut that doesn't split the image evenly ("1000 px doesn't split into 12 columns") or gives a tile under 1 px shows the problem and disables **Apply**.
    - **Apply** creates the sheet with E5b1's `SetTilesheet` (one undoable step); the grid stays and cells can be chosen and painted. **Cancel** closes the panel; nothing is created.
    - Re-cutting a sheet that is already set up is E6.
  - **New types:**
    - `Tiles/SheetCutViewModel` (`ObservableObject`): the cut being edited for one sheet image, and the tile size and problem it gives.
      - `SheetCutViewModel(TilesheetDefinition sheet, (int Width, int Height) imageSize)`: starts from the sheet's cut, columns and rows computed with `ColumnsIn`/`RowsIn`.
      - `Columns`, `Rows`, `Margin`, `Spacing` (observable inputs); `TileWidth`, `TileHeight` (read-only, computed).
      - `Problem` (null when the cut is whole), `Summary`.
      - `PreviewSheet`: the sheet as the fields stand, for the grid preview.
      - `ToSheet()`: the cut as a `TilesheetDefinition` with the same id and file; throws with `Problem` when there is one.
  - **Changes:**
    - `Tiles/TileBrowserViewModel`: `Cut` (`SheetCutViewModel?`, the open panel); `SetUpSheetCommand` opens `Cut` instead of creating the sheet; `ApplyCutCommand` (can execute when `Cut.Problem` is null: `SetTilesheet(Cut.ToSheet())`, closes the panel); `CancelCutCommand`.
    - `Tiles/TileBrowserView`: the Cut expander; draws the marks with `Cut.PreviewSheet` while it is open.
  - **Tests:**
    - `SheetCutViewModelTests`:
      - `Columns_ImageSplitsEvenly_SetsTileWidth`;
      - `Columns_ImageDoesNotSplit_ReportsProblem`;
      - `Margin_Set_RecomputesTileSize`;
      - `ToSheet_ColumnsChanged_KeepsIdAndFile`.
    - `TileBrowserViewModelTests`:
      - `SetUpSheetCommand_ImageNotSetUp_OpensCutWithGuessedColumnsAndRows` (replaces E5b1's `SetUpSheetCommand_ImageNotSetUp_AddsTheGuessedSheetAndShowsIt`);
      - `ApplyCutCommand_NewSheet_AddsItAndShowsTheGrid`;
      - `ApplyCutCommand_CutWithProblem_CannotExecute`;
      - `CancelCutCommand_NewSheet_AddsNothing`.
  - **Verify by hand:**
    - [ ] Choose `Grass3.png`, Set up: the panel shows `grass_3` and a guessed grid; adjust Columns and Rows until the preview lines up with the art; Apply; paint from it.
    - [ ] Set up `Floor.png` (64 x 64): the guess is 32 px (2 x 2 cells); Cancel: still "(not set up)".
    - [ ] Type columns that don't divide the width: the problem shows and Apply is greyed.
- **Done, with deviations:** while the Cut panel is open the image stays at its own size (the scale doesn't jump as a field is typed); the grid uses `PreviewSheet`, null (no grid) when the fields give no tile. Choosing another image closes the panel. Extra tests: `Constructor_SheetCut_ShowsItsColumnsAndRows`, `Columns_TilesUnderOnePixel_ReportsProblemAndHasNoPreview`, `ToSheet_CutWithProblem_ThrowsWithIt`. Review: a margin as wide as a cell and its spacing is a problem (the saved sheet would hold one more column or row); Set up is disabled while the panel is open; tests added for closing on another image, Apply's CanExecuteChanged and each problem message. Left: huge column or row counts draw one mark per cell (a slow preview), and a margin past int range overflows.
