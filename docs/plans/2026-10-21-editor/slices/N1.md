# N1. An NPC in the game

Part of [the editor plan](../README.md). Design: [design.md](../design.md), "NPCs", "Core changes", "Data changes", "Tunables" (NPC placeholders); ADR 0015; questions 127-132 (placeholders).

- **N1. An NPC in the game** (Core + Data + Game + content, about 250 lines)
  - **Goal:**
    - On the `start` map, a villager stands a few cells from the spawn, drawn from the placeholder field sprite (the standing frame facing down, question 128). The player can't walk through its feet (default outline, question 129), walks behind its head, and pressing confirm while facing it shows "Talk" then a dialogue with the speaker "Villager".
    - Everything comes from content: the NPC is an object `villager` (category "NPC") whose `fieldSpriteFile` is `npc_placeholder.png`, placed with an Interact event holding a Dialogue step, the way chests and signs are made today. Interaction, collision and events need no change.
    - **Known gap until N2:** the editor shows the NPC as an empty box (it draws objects from tiles only); it can be selected, moved and deleted.
  - **Core:**
    - `Maps/ObjectDefinition.FieldSpriteFile` (`string?`, null for objects drawn from tiles): the field sprite the object is drawn from, a file in the field-sprite art folder.
  - **Data:**
    - `Maps/ObjectCatalogValidator`: an object has tiles or a field sprite, not both and not neither ("tiles or fieldSpriteFile must be set; an object without either draws nothing"); a field-sprite object has no above-player zones ("abovePlayerZones aren't drawn for a field-sprite object").
    - `Art/ArtReferenceCheck.FindProblems`: every object's field sprite exists in `field-sprites/`, named exactly (case included), "Named by object 'villager'".
  - **Game:**
    - `Exploration/FieldSpriteFrame` (static, pure): the source rectangle of one frame of a field sprite, for a facing and a frame index (48 px frames, rows from `WalkAnimation.RowOf`). `ExplorationScene.DrawPlayer` uses it instead of its inline rectangle.
    - `Exploration/MapView.DrawObject`: a field-sprite object draws its standing frame (`Facing.Down`, frame 0) over its cells; tile objects as today.
  - **Content:**
    - `content/art/field-sprites/npc_placeholder.png`: a copy of `player.png` (question 130), so its frame layout is the player's.
    - `content/objects.json`: `villager` (1 x 1, category "NPC", `fieldSpriteFile` `npc_placeholder.png`, `tiles` empty, collision outline over the lower half: (0.2, 0.5), (0.8, 0.5), (0.8, 1), (0.2, 1)).
    - `content/map-layouts/start.json`: one placed `villager` with an Interact event, prompt "Talk", one Dialogue step (speaker "Villager", two placeholder lines), placed away from the paths `StartMapScenarios` walks.
  - **Existing tests this breaks:** `ObjectCatalogValidatorTests.Validate_NoTiles_ThrowsNamingTheObject` (its expected message changes to the new wording; rename to `Validate_NeitherTilesNorSprite_ThrowsNamingTheObject`). Repository-content tests (`StartMapScenarios`, the content load test) must still pass with the villager placed; if a scenario walks through its cell, move the villager, not the scenario.
  - **Tests:**
    - `ObjectCatalogValidatorTests` (Data): `Validate_SpriteObjectWithTiles_ThrowsNamingTheObject`, `Validate_SpriteObjectWithZones_ThrowsNamingTheObject`, `Validate_SpriteObjectWithoutTiles_Passes`.
    - `ArtReferenceCheckTests` (Data): `FindProblems_MissingObjectFieldSprite_NamesTheObject`.
    - `ContentCatalogLoaderTests` (Data): `Load_RepositoryContent_VillagerUsesThePlaceholderSprite`.
    - `FieldSpriteFrameTests` (Game): `SourceOf_FacingDownFirstFrame_IsTheDownRowsFirstCell`, `SourceOf_ThirdFrame_MovesTwoFramesRight`.
    - Core: `ExplorationStateTests`: `Interact_FacingVillagerOnStartMap_StartsItsTalkEvent` (repository content, fixed seed), `Move_IntoVillagersFeet_IsBlocked`.
  - **Verify by hand:**
    - [ ] F5, new game: the villager stands near the spawn, same look as the player, facing down.
    - [ ] Walk into its feet: blocked; walk behind its head: the player passes (drawn by depth).
    - [ ] Face it: "Talk" shows; confirm: the dialogue with "Villager" plays; it can be talked to again.
    - [ ] Save near it, load: it is there; nothing else in the save changed.
