# I1. The current input device and button names

Part of [the demo retirement plan](../README.md). Design: [design.md](../design.md), key decision 3; tunables "device in use" and "button names"; decisions 50, 138; question 147.

- **I1. The current input device and button names** (Game, about 150 lines)
  - **Goal:**
    - The Game knows whether the player is using the keyboard or a controller.
    - It can name the key or pad button bound to any game button on that device.
    - Nothing on screen changes yet; G1a's prompt is the first user (it lands next).
  - **New types:**
    - `Input/InputDevice` (enum: `Keyboard`, `Controller`): the device the player is using.
    - `Input/ButtonLabels` (static, pure): the name of the key or pad button bound to a game button on a device.
      - `static string Of(GameButton button, InputDevice device)`: the first binding for that device in `InputBindings` (`Keys.E` gives "E", `Buttons.A` gives "A").
      - The strings are built once per (button, device) and cached, so nothing is allocated per frame.
      - A button with no binding on that device throws `InvalidOperationException` naming both. The tab buttons have no key (question 92); no caller asks for those.
  - **Changes:**
    - `Input/InputFrame` gains `Device`.
    - `Input/InputReader` keeps the last device:
      - a bound key pressed this update means `Keyboard`;
      - a bound pad button pressed, or the stick past `StickReader`'s dead zone, means `Controller`;
      - otherwise it stays as it was;
      - it starts as `Keyboard` (question 147 placeholder).
  - **Tests:**
    - `InputReaderTests`:
      - `Read_NothingPressed_DeviceIsKeyboard`;
      - `Read_PadButtonPressed_SwitchesToController`;
      - `Read_StickPastDeadZone_SwitchesToController`;
      - `Read_StickInsideDeadZone_KeepsTheDevice`;
      - `Read_KeyPressedAfterPad_SwitchesBackToKeyboard`;
      - `Read_NothingPressedAfterPad_StaysController`.
    - `ButtonLabelsTests`:
      - `Of_ConfirmOnKeyboard_IsItsFirstKey`;
      - `Of_ConfirmOnController_IsA`;
      - `Of_SameButtonTwice_ReturnsTheSameString`;
      - `Of_ButtonWithoutPadBinding_ThrowsNamingIt`.
  - **Verify by hand:** none (nothing drawn yet; G1a checks it on screen).
