# A1. The inventory category rail takes the cursor: Left to the rail, Up/Down filter, Right back

Part of [the code health plan](../README.md). Design: [design.md](../design.md), "The inventory rail"; question 152 (placeholder controls), question 92 (no keyboard key for the tab buttons).

- **A1. The rail takes the cursor** (Game + content, about 220 lines)
  - **Why the rail can't be used today:**
    - Only `PreviousTab`/`NextTab` change the category, and only the controller's shoulder buttons are bound to them. `InputBindings` gives them no key (question 92), so on the keyboard the filter can't be reached at all.
    - Left and Right do nothing on the page.
    - Nothing on screen says the rail can be chosen. The footer hint ("Choose an item to read about it. Confirm to use it.") doesn't mention it.
  - **Write first, and see it fail:** `InventoryPageTests: Update_LeftThenDown_ShowsConsumables`. Today Left does nothing and Down moves the row, so the category stays All.
  - **Goal** (question 152 placeholder):
    - The page opens on the list, as now.
    - **Left** from the list puts the cursor on the rail.
    - On the rail, **Up/Down** change the category, and the list filters at once.
    - **Right** or **Confirm** on the rail go back to the list's first row. Confirm there never uses an item.
    - **Cancel** on the rail leaves the page, as on the list.
    - The shoulder buttons still change the category from either side.
    - The footer hint says which side has the cursor and how to switch.
    - The drawing stays plain: the rail's selected tab is lit as today. A2 adds the pointer.
  - **New types:**
    - `Menus/CategoryRail` (pure): which inventory category is chosen, and whether the cursor is on the rail.
      - Holds the rail's tabs (category, heading message id, icon file), moved from `InventoryPage._tabs` and its private `CategoryTab` record, which becomes `Menus/CategoryTab`.
      - `IReadOnlyList<CategoryTab> Tabs`, `InventoryCategory Category`, `int Selected`, `bool HasCursor`.
      - `void MoveUp()`, `void MoveDown()`: wrap as today.
      - `void TakeCursor()`, `void ReturnCursor()`.
      - `void Reset()`: All, cursor on the list, used by `Open`.
  - **Changes:**
    - `Menus/InventoryPage`:
      - `MoveThroughList` splits into a list branch (Left takes the cursor to the rail; Up/Down move the row) and a rail branch (Up/Down move the category; Right or Confirm return to the list).
      - The shoulder handling calls the rail from either side.
      - A category change still calls `ShowRowsFrom(0)`.
      - `Update` checks the rail first, so Confirm on the rail never reaches `OpenItemUse`.
      - `Hint` returns the rail hint or the list hint, both formatted once in the constructor.
      - `Category` reads `_rail.Category`.
      - New `bool IsChoosingCategory => _rail.HasCursor`.
    - `content/text/ui.json` and `Ui/MessageIds`:
      - new `menu_hint_inventory_categories`: "Choose a category. Right: back to the items." (placeholder text);
      - `menu_hint_inventory` becomes "Choose an item to read about it. Confirm to use it. Left: categories."
    - `docs/plans/backlog.md`: the `InventoryPage` split line says the rail state left in A1 and its drawing in A2; rows and list view still wait.
  - **Tests:**
    - `InventoryPageTests`:
      - `Update_LeftThenDown_ShowsConsumables`;
      - `Update_LeftFromList_PutsTheCursorOnTheRail`;
      - `Update_RightOnRail_ReturnsToTheListOnItsFirstRow`;
      - `Update_ConfirmOnRail_ReturnsToTheListAndUsesNothing` (a guard: the inventory is unchanged and no target picker opens);
      - `Update_UpOnRailFromAll_WrapsToArmor`;
      - `LeavesOnCancel_OnRail_IsTrue`;
      - `Hint_AfterLeft_IsTheCategoryHint` and `Hint_BackOnTheList_IsTheListHint`, each starting from the other hint (refresh rule);
      - `Open_AfterLeavingFromTheRail_StartsOnTheList`;
      - `Update_LeftWhileChoosingTarget_LeavesTheRailAlone`: the target picker answers input first.
    - `CategoryRailTests`:
      - `MoveDown_FromArmor_WrapsToAll`;
      - `Reset_AfterMoving_IsAllWithTheCursorOnTheList`.
    - The existing `InventoryPageTests` pass unchanged; shoulder buttons are still `PreviousTab`/`NextTab`.
