# P1. The party sidebar lists active and reserve, marks the shown member, scrolls to it

Part of [the code health plan](../README.md). Design: [design.md](../design.md), "The party sidebar"; decisions 145, 146 (answered in substance); questions 153 (placement, placeholder: the right column), 154 (reserve look), 155 (switch buttons, placeholder: Left/Right and shoulders).

- **P1. Sidebar behavior** (Game + content, about 250 lines)
  - **Goal:**
    - The sidebar lists every recruit: the active members in party order, then the reserve.
    - On a page that shows one member (Status, Equipment), the sidebar marks that member's card and follows when the player switches member with the page's existing buttons (Left/Right and shoulders).
    - With seven recruits and room for six cards, the sidebar scrolls so the marked card is always visible. The window moves only when the marked card would leave it.
    - On other pages (Inventory), nothing is marked.
    - The marked card uses `MemberCardView`'s existing selected look (`IsSelected: true`). The reserve look and the pointer come in P2.
    - The member pages' hints name the switch buttons.
  - **New types:**
    - `Menus/IMemberPage`: a menu page that shows one party member at a time.
      - `PartyMember Shown { get; }`.
      - `StatusPage` and `EquipmentPage` implement it with their existing `Shown`. Two implementers, so the interface has a reason.
  - **Changes:**
    - `Menus/SidebarCard`: gains `bool IsReserve`; `Of(member, isReserve)`.
    - `Menus/PartySidebar`:
      - lists `ActiveMembers` then `ReserveMembers`;
      - `IsSameOrder` walks both lists without allocating, since it runs every update;
      - `Refresh(PartyMember? shown)` updates the cards as today, then sets `int? ShownIndex` and keeps `int FirstVisible` so the shown card is inside the window;
      - `const int VisibleCards = 6`, a placeholder: 6 × (120 + 12) px fits the 864 px page height.
    - `Menus/PartySidebarView`: draws cards `FirstVisible` to `FirstVisible + VisibleCards - 1`, and passes `IsSelected: index == ShownIndex`.
    - `Menus/GameMenuScene.Update`: `_sidebar.Refresh((page as IMemberPage)?.Shown)`.
    - `content/text/ui.json`: `menu_hint_status` becomes "Left and Right: change character." The equipment hint adds "Left and Right: change character." (placeholder texts).
    - `docs/map.md`: the Menus row lists `IMemberPage`.
  - **Tests:**
    - `PartySidebarTests`:
      - `Cards_ReserveMember_IsNotListed` is replaced by `Cards_ReserveMember_IsListedAfterTheActive`. This is a changed expectation from decision 146, not a weakened assertion; say so in the commit.
      - `Cards_ReserveMember_IsReserve`;
      - `Refresh_ShownMember_MarksItsCard`;
      - `Refresh_NoShownMember_MarksNone`;
      - `Refresh_ShownMemberBelowTheWindow_ScrollsToShowIt` (seven recruits, shown the last; starts with `FirstVisible` 0);
      - `Refresh_ShownMemberAlreadyVisible_KeepsTheWindow`;
      - `Refresh_MemberMovedToReserve_ListsItAfterTheActive`.
    - `GameMenuSceneTests`:
      - `Update_RightOnStatus_SidebarMarksTheNextMember`;
      - `Update_InventoryOpen_SidebarMarksNoMember`.
    - The other existing sidebar and page tests pass unchanged.
