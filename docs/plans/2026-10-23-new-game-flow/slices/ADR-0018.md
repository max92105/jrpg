# ADR 0018: Audio files and playback

Part of [the new-game flow plan](../README.md). Design: [design.md](../design.md), "The voice-over path".

- **ADR 0018: Audio files and playback** (checkbox step before A1a; write with `/adr`)
  - **Question:** how does the game load and play sound, starting with voice-overs? It must use no NuGet package, and the update path must not touch a device (ADR 0008).
  - **Options** (README, "ADRs"):
    - A. WAV through MonoGame's `SoundEffect.FromFile` (recommended);
    - B. OGG through `Song`/`MediaPlayer`;
    - C. a package.
  - **Record with the decision:**
    - Files live in `content/audio/<kind>/`, starting with `voices/`, checked at startup by exact name, like art (ADR 0009). The encoding isn't checked: a file that won't load is reported once, by name, and plays silent.
    - Scenes write the wanted voice into a plain `VoiceChannel`; the host's `VoicePlayer` plays it after each update.
    - The audio system is touched once at load, so a missing device shows at startup. The game then reports it once and runs silent.
    - Music and SFX extend this in their own plan, which may pick `Song` for streaming music.
  - **Before writing:** check in MonoGame 3.8.6 DesktopGL's source or docs which WAV encodings `SoundEffect.FromFile` accepts, and note them for whoever replaces the placeholder voice.
  - **Done when:** `docs/decisions/0018-audio-files-and-playback.md` is accepted by the developer and indexed.
