# C1b1. Classes carry their base stats and growth per level

Part of [the new-game flow plan](../README.md). Design: [design.md](../design.md), "Tunables and placeholders" (classes), "Core changes". ADR 0017. Split from C1b at the size check (the developer, 2026-10-24); C1b2 makes members use it.

- **C1b1. Classes carry their base stats and growth per level; the one formula** (Core + Data + content, about 170 lines; decision 164; question 180)
  - **Goal:**
    - Each class in `classes.json` has `base` (max HP, max MP, attack, defense at level 1) and `growth` (what each level after the first adds).
    - `ClassGrowth.StatsAt(class, level)` gives `base + growth × (level − 1)`.
    - Data refuses impossible numbers.
    - Nothing reads the formula yet; C1b2 does.
  - **New types (Core):**
    - `Party/ClassStats`: max HP, max MP, attack and defense, as a class's base or its growth. `record ClassStats(int MaxHp, int MaxMp, int Attack, int Defense)`.
    - `Party/ClassGrowth` (static, pure): the stats a class gives at a level, the one formula, with its reason (ADR 0017).
  - **Changes:**
    - Core: `ClassDefinition(Id, Name, Description, ClassStats Base, ClassStats Growth)`.
    - Data `ClassCatalogValidator`: base max HP at least 1; base max MP, attack and defense, and every growth, at least 0. Messages name the class and the field.
    - Content `classes.json`: `base` and `growth` per the design table (placeholders; question 180).
  - **Tests:**
    - `ClassGrowthTests`:
      - `StatsAt_LevelOne_IsBase`
      - `StatsAt_LevelFive_AddsFourGrowths`
      - `StatsAt_LevelBelowOne_Throws`
    - `ClassCatalogValidatorTests.Validate_InvalidStat_ThrowsNamingTheClassAndField` (theory)
    - `ContentCatalogLoaderTests`: the nine classes carry base stats.
  - **Verify by hand:** none; nothing shows the numbers until C1b2.
  - **Done, with deviations:** as planned.
    - `ClassGrowth` is public (Core types used by the Game are); the Game reads it from S2 on. The class numbers are the design table's placeholders, unbalanced until C1b2's simulation check.
    - Added beyond the plan: `Validate_ZeroGrowth_DoesNotThrow`, since a class may never improve a stat.
    - Review (Critical fixed): `ClassGrowth`'s summary is rewrapped to 120 columns. `ClassDefinition` explains `Base` and `Growth` in its summary instead of param tags, which had forced empty tags for `Id`, `Name` and `Description`. Two long test lines are split.
