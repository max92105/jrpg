# K1. Cinematics in content, with generated placeholder stills

Part of [the new-game flow plan](../README.md). Design: [design.md](../design.md), "Core changes", "Content format", "Tunables and placeholders" (intros, stills).

- **K1. Cinematics in content, with generated placeholder stills** (Core + Data + content, about 270 lines; decisions 159, 172, 173)
  - **Goal:**
    - `cinematics.json` defines one placeholder intro per leader choice, and each leader choice names its intro.
    - A broken cinematic, an unknown intro id or a missing still stops the start with the file named, as other content does.
  - **New types:**
    - Core `Cinematics/CinematicDefinition`: a sequence of stills shown in order. `required string Id`, `required IReadOnlyList<CinematicShot> Shots`. A1a adds the voice file.
    - Core `Cinematics/CinematicShot`: one still held for a time, with an optional caption.
      - `required string ImageFile` (in `art/cinematics/`);
      - `required double Seconds` (above 0; set to match the voice, decision 173);
      - `string? Caption` (the subtitle, decision 172);
      - `Duration => TimeSpan.FromSeconds(Seconds)`.
    - Data `Cinematics/CinematicCatalogValidator`:
      - unique ids; at least one shot; no null shot;
      - `imageFile` not blank; `seconds` above 0; `caption` null or not blank.
      - Messages name the cinematic id and the shot's index.
  - **Changes:**
    - Core:
      - `Content/ContentCatalog.Cinematics`;
      - `Content/LeaderChoice.IntroCinematicId` (required).
    - Data:
      - `ContentCatalogLoader` reads `cinematics.json` before `new-game.json`;
      - `NewGameReferences` gains the cinematic ids, and `NewGameValidator` checks each `introCinematicId`;
      - `ContentWriter.WriteMap` passes them.
    - Data Art:
      - `ArtFolders.Cinematics = "cinematics"`;
      - `ArtReferenceCheck` adds every shot's image by exact name, "Named by cinematic 'zanyr_intro'".
    - Content:
      - `cinematics.json`: one intro per L1 leader choice, three 4 s shots each, captions per the design table;
      - `new-game.json`: an `introCinematicId` per choice;
      - `art/cinematics/Placeholder1.png` to `Placeholder3.png`: 640 x 360, made once by a PowerShell `System.Drawing` script (a dark gradient and "Still n" in large text). Record the command in the Done note.
    - `docs/plans/backlog.md`: `TextureLibrary` keeps every still for good, which matters once real full-screen stills arrive.
    - Tests:
      - `ContentCatalogBuilder` gets `WithCinematics` and an empty default;
      - `WithLeader` gives its choice a test intro id and adds that intro.
  - **Tests:**
    - `CinematicCatalogValidatorTests`:
      - `Validate_ValidCinematic_DoesNotThrow`
      - `Validate_InvalidField_ThrowsNamingTheField` (theory: no shots, null shot, blank image, zero seconds, negative seconds, blank caption)
      - `Validate_DuplicateId_ThrowsNamingTheId`
    - `NewGameValidatorTests`: theory row `leaderChoices 'sarxian': introCinematicId 'nope' is not a known cinematic.`
    - `ArtReferenceCheckTests.FindProblems_MissingStill_NamesTheCinematic`
    - `ContentCatalogLoaderTests.Load_RepositoryContent_EveryLeaderHasAnIntro`
  - **Verify by hand:** the game starts. Renaming `Placeholder2.png` stops the start, naming the still and the cinematics that use it.
