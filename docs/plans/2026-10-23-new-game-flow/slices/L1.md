# L1. A new game starts with the chosen leader alone

Part of [the new-game flow plan](../README.md). Design: [design.md](../design.md), "Core changes", "Content format", key decisions 2 and 3.

- **L1. A new game starts with the chosen leader alone; the party may hold 5** (Core + Data + content, about 300 lines, plus about 50 one-argument call-site edits; decisions 158, 163, 176)
  - **Goal:**
    - Core starts a new game from a leader chosen among the content's leader choices, alone in the party.
    - Until S1, the game passes the first choice.
    - `maxActiveMembers` is 5.
  - **New types (Core):** `Content/LeaderChoice`, one character a new game may start led by: `public sealed record LeaderChoice { public required string MemberId { get; init; } }`. K1 adds `IntroCinematicId`.
  - **Changes:**
    - Core `Content/NewGameDefinition`:
      - adds `required IReadOnlyList<LeaderChoice> LeaderChoices` ("in the order the choice screen lists them");
      - removes `RecruitedMemberIds` and `ActiveMemberIds`.
    - Core `Session/GameSession.StartNew(ContentCatalog catalog, string leaderId, IRandom random)`:
      - the members and the active party are `[leader]`;
      - it throws `ArgumentException` naming the id when no `LeaderChoice` has it.
    - Data `Content/NewGameValidator`:
      - `leaderChoices`: at least one entry; no null entry or blank `memberId`; known and distinct member ids;
      - the old recruit and active checks go.
    - Data `Content/NewGameReferences`: drop `Party` if nothing else reads it, and update `ContentWriter.WriteMap`, which builds it.
    - Content:
      - `new-game.json`: `leaderChoices`: sarxian, jazog, teelle, zaruk, zanyr, thaali. Sarxian is first, so the game still starts as him. Kamilia is left out, since C2 removes her. `recruitedMemberIds` and `activeMemberIds` go.
      - `rules.json`: `maxActiveMembers` 5.
    - Game `Flow/SessionTransitions.StartNewGame()` passes `catalog.NewGame.LeaderChoices[0].MemberId`. This is a known gap: S1 passes the chosen leader.
    - Tests:
      - `ContentCatalogBuilder.WithLeader(string memberId)` sets the new game's single leader choice. The builder's default new game has no choice, so a builder test that starts a game says who leads.
      - Every `GameSession.StartNew(catalog, random)` call gains the leader id. Repository-content tests pass `"sarxian"`.
      - Tests that relied on the old reserve start with the members they need: Party-page tests moving members between active and reserve now build their party, or recruit through a test helper.
      - Record the test count before and after.
  - **Tests:**
    - `GameSessionTests`:
      - `StartNew_ChosenLeader_LeadsAlone`
      - `StartNew_LeaderNotAmongChoices_Throws`
    - `NewGameValidatorTests`, with theory rows replacing the old ones:
      - `leaderChoices must list at least one character.`
      - `leaderChoices has unknown party member id 'nobody'.`
      - `leaderChoices lists 'sarxian' more than once.`
      - `leaderChoices has a null entry or an empty memberId.`
    - `RepositoryNewGameTests.StartNew_RepositoryContent_EveryLeaderChoiceStarts`
  - **Verify by hand:** New Game starts on the start map as Sarxian, alone. The Party page shows one member, and the battle shows one member.
