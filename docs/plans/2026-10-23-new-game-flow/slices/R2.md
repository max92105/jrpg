# R2. Placeholder recruit points on the start map

Part of [the new-game flow plan](../README.md). Design: [design.md](../design.md), "Tunables and placeholders" (recruit points), "Recruiting".

- **R2. Placeholder recruit points on the start map** (content + tests, about 100 lines; decision 163)
  - **Goal:**
    - The start map holds nine NPCs, one per character, each with a recruit event for its character. That way any party can be assembled for testing.
    - Talking to the leader's own NPC says they're already in the party.
  - **Changes:**
    - Content:
      - `content/maps/start.json` (and its layout, if objects live there): nine NPC objects in a row in an open area, away from the start position and the exits.
      - Each NPC uses the existing NPC sprite, with an interaction event of a one-line dialogue ("A placeholder recruit point.") and then the recruit step.
      - Place them with the editor if that is quicker, then check the JSON diff.
    - Nothing else: this slice is content, and the code is R1a's.
  - **Tests:** `RepositoryStartMapTests.StartMap_RepositoryContent_OffersEveryCharacterToRecruit`. Every leader choice's member is named by exactly one recruit step on the start map.
  - **Verify by hand:**
    - New game as Omer. Talk to the NPCs: four join the active party (five in all), and the rest go to the reserve.
    - The Party page shows them.
    - Omer's own NPC says he's already in the party.
    - Save and Continue: the recruits are still there.
