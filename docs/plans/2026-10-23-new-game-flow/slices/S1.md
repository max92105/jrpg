# S1. New Game opens the character choice

Part of [the new-game flow plan](../README.md). Design: [design.md](../design.md), "The flow" and "Structure".

- **S1. New Game opens the character choice** (Game, about 280 lines; decisions 157, 158, 178)
  - **Goal:**
    - New Game fades to a screen listing the leader choices by name, with the cursor on the first.
    - Up and Down move the cursor and wrap.
    - Confirm fades to the map with that character leading. S1b puts "Begin as X?" in between.
    - Cancel fades back to the title.
    - Plain draw: the dimmed title background and the names in a column on the left, the highlighted one white and the rest grey. The look comes in S3a.
  - **New types (Game):**
    - `NewGame/LeaderChoiceMenu` (pure): the leaders a new game offers and which one the cursor is on.
      - `LeaderChoiceMenu(IReadOnlyList<LeaderChoice> choices)`.
      - `Choices`, `Selected`.
      - `LeaderChoice? Update(InputFrame input)`: Up and Down move a `ListCursor`; Confirm returns `Selected`.
    - `NewGame/LeaderChoiceScene` (`IScene`): the screen after New Game.
      - `LeaderChoiceScene(ScreenText text, ContentCatalog catalog)`.
      - Names are looked up and measured once in the constructor.
      - Returns `LeaderChosen` once, then null.
      - Cancel returns `TitleRequested` once, and wins over Confirm in the same update.
    - `Scenes/LeaderChosen(LeaderChoice Choice)`: start a new game led by this choice.
  - **Changes:**
    - `Scenes/NewGameRequested` summary: "Show the leader choice for a new playthrough."
    - `Flow/SessionTransitions`:
      - `ShowLeaderChoice()` replaces every scene with the choice;
      - `StartNewGame(LeaderChoice choice)` replaces L1's first-choice gap.
    - `Flow/GameFlow.ApplyRequestOnceBlack`:
      - `NewGameRequested` calls `_sessions.ShowLeaderChoice()`, and the session stays null;
      - a `LeaderChosen` case sets `Session = _sessions.StartNewGame(chosen.Choice)`.
      - If this makes CA1502 fail, split the switch here (design.md, "The flow").
    - `Flow/SceneFactory.CreateLeaderChoice()`.
    - `content/text/ui.json` and `Ui/MessageIds`: `leader_choice_title` ("Choose your leader"), drawn at the top.
  - **Tests:**
    - `LeaderChoiceMenuTests`:
      - `Selected_New_IsFirstChoice`
      - `Update_Down_SelectsNextChoice`
      - `Update_UpOnFirst_WrapsToLast`
      - `Update_Confirm_ReturnsSelectedChoice`
      - `Update_NothingPressed_ReturnsNothing`
    - `LeaderChoiceSceneTests` (repository content; the leader is picked by id with a helper that presses Down until `Selected.MemberId` matches, since C2 reorders the list):
      - `Update_ConfirmOnZanyr_RequestsZanyr`
      - `Update_ConfirmTwice_RequestsLeaderOnce`
      - `Update_Cancel_RequestsTitle`
      - `Update_CancelAndConfirmTogether_RequestsTitle`
    - `GameFlowTests`:
      - `Update_NewGameConfirmedFadeReachesBlack_StartsOnTheStartMap` becomes `..._ShowsChoiceWithoutSession`.
      - New: `Update_LeaderConfirmedFadeReachesBlack_StartsLedByThem`, `Update_CancelOnChoice_ReturnsToTitleWithoutSession`.
      - The `StartedFlow` helper confirms New Game, waits out the fade, then confirms the choice. Its catalog's choices hold Sarxian only (`WithLeader("sarxian")`).
  - **Verify by hand:**
    - New Game fades to the list; Up and Down move it.
    - Confirm on Zanyr starts the map with Zanyr alone.
    - Cancel returns to the title, with Continue still selected when there's a save.
