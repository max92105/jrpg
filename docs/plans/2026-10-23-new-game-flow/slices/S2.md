# S2. The choice shows who each character is

Part of [the new-game flow plan](../README.md). Design: [design.md](../design.md), "Structure".

- **S2. The choice shows the class, description, summary and level 1 stats** (Game, about 220 lines; decisions 158, 168, 169)
  - **Goal:**
    - Each row in the list shows "Name, Class".
    - Right of the list, using most of the screen, the highlighted character's information shows in plain text:
      - the class name and description;
      - the summary;
      - the level 1 stats (Level 1, HP, MP, Attack, Defense).
    - Long texts wrap. The look comes in S3a and S3b.
  - **Changes:**
    - `NewGame/LeaderChoiceScene`:
      - row labels "Name, Class" are measured in the constructor;
      - each choice's information is built once, in the constructor, and indexed like `LeaderChoiceMenu.Choices`. That covers the class description, the summary and the stat lines, which read `ClassGrowth.StatsAt(class, 1)` and are formatted through `NumberText`.
      - Description and summary are laid out once at a fixed width with FontStashSharp's `RichTextLayout`, as `DialogueBox` does, so drawing allocates nothing.
    - `content/text/ui.json` and `Ui/MessageIds`: the stat labels, reusing the Status page's ids where they exist (`StatusHp` and the like).
  - **Tests (`LeaderChoiceSceneTests`, repository content):**
    - `ShownClassName_CursorOnJazog_IsBarbarian`
    - `ShownStats_CursorOnOmer_AreTheMageAtLevelOne`
    - These read small internal accessors on the highlighted choice's information (`tests.md`: a seam beats a vacuous test).
  - **Verify by hand:** moving the cursor changes the class, description, summary and numbers at once. A long summary wraps inside its area.
