# T2. The defeat screen hides the loads it can't use

Part of [the new-game flow plan](../README.md). Design: [design.md](../design.md), "Replacement mapping".

- **T2. The defeat screen hides the loads it can't use** (Game, about 80 lines; decision 175)
  - **Goal:** with no readable save, the defeat screen lists only Main Menu. With one, it lists Load Last Save, Load and Main Menu as today. Nothing is greyed.
  - **Changes (Game):**
    - `Battle/DefeatMenu`:
      - `Entries` becomes an instance list built from `hasReadableSave`;
      - `IsEnabled` is deleted;
      - the cursor starts on the first entry.
    - `Battle/DefeatScreenView`:
      - labels are built from the menu's entries;
      - the greyed color goes;
      - `UiTheme.TextDisabled` goes too if nothing else uses it (the build's unused-code check tells).
    - Any test or view that reads the static `DefeatMenu.Entries` uses the instance.
  - **Tests (`DefeatMenuTests`):**
    - `Entries_NoReadableSave_ListsMainMenuOnly`
    - `Entries_ReadableSave_ListsBothLoadsAndMainMenu`
    - Existing tests that pressed past a greyed entry pick entries by what they are.
  - **Verify by hand:** lose a battle with no save (rename the save folder): only Main Menu shows. With a save: three entries.
