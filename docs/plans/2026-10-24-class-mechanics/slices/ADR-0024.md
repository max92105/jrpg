# ADR 0024: Lasting resources and rest

Part of [the class mechanics plan](../README.md). Design: [design.md](../design.md), "Key design decisions" 8, "Content format" (clarity). Decision 198; questions 219-223.

- **ADR 0024: Lasting resources and rest** (checkbox step before LR1; write with `/adr`)
  - **Question:** every class should need a rest (decision 198). The cleric's faith stays lowered until rest; the mage's starting mana drops with tiredness. Where does that lasting state live, how does it reach a battle, how is it saved, and what restores it?
  - **Options:**
    - A. a resource marked `isLasting` keeps its amount on the member between battles (recommended):
      - a battle starts from the member's amount and writes it back when it ends;
      - a `perBattleFought` gain applies when a battle ends;
      - saves keep the amounts by resource id;
      - a rest refills them to their starting amount;
      - an optional strain rule lets a lasting resource lower another resource's start ("each missing Clarity point lowers starting mana by 1").
      Faith is simply lasting; the mage gets a lasting Clarity. The other classes' costs (question 220) become content.
    - B. a separate per-member strain counter per class, outside resources. A second meter model with its own triggers, save field and display, for the same idea.
    - C. lasting statuses that survive the battle. Statuses are battle-only by ADR 0021, and they count turns, not battles.
  - **Record with the decision:**
    - Saves gain `lastingResources` per member (format 2 → 3, older saves refused, ADR 0022). Repair drops unknown ids and clamps to 0..max.
    - A rest (inn step, rest item) calls one Core method, `PartyMember.Rest()`. What it restores is question 221 (placeholder: full HP, revive, lasting resources).
    - Only lasting resources carry over; every other resource starts each battle afresh (question 223).
  - **Done when:** `docs/decisions/0024-lasting-resources-and-rest.md` is accepted and indexed.
