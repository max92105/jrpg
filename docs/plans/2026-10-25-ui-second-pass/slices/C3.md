# C3. `EventPresenter` split: the run of stills moves out

Part of [the UI second pass plan](../README.md). Design: [design.md](../design.md), "Replacement mapping", "Clean-up selection".

- **C3. `EventPresenter` split: the run of stills moves out** (Game, mechanical, about 220 lines)
  - **Goal:** `Exploration/EventPresenter` (285 lines) keeps showing steps (pages, warps); a cutscene's stills, with their black lead-in and lead-out and their skip, move to a type of their own, so X1 can add the rest fade without crossing 300 lines. The backlog's split ("dialogue pages apart from still timing").
  - **New types:** Game `Exploration/StillRun` (internal sealed): one run of cutscene stills: the black lead-in, each still's time and skip, the black lead-out.
    - It takes what the still code uses today (the `ExplorationState`, the `StillView`); count `EventPresenter`'s still fields and methods (`_still`, `_leadInLeft`, `_leadOutLeft`, `LeadIn`, `LeadOut`, `ShowStill`, `RunLeadIn`, the lead-out in `Update`, `StayBlackIntoAWarp` if only stills use it) before moving: what moves is those, nothing else.
    - It exposes what the presenter reads: `bool IsShowing`, `bool IsLeadingOut`, `float Blackness`, `Update`/`Draw` for its part.
  - **Changes (Game):** `EventPresenter` delegates to a `StillRun`; `IsBusy`, `Blackness` and `IsShowingStill` read it. `LeadIn`/`LeadOut` move with it; tests that read `EventPresenter.LeadIn` read `StillRun.LeadIn` (a mechanical prefix edit).
    - Remove the `EventPresenter` half of the backlog's "near 300" line (`ExplorationState` stays).
    - `docs/map.md`, Exploration line: `StillRun`.
  - **Tests:** none new; `EventPresenterTests` (304 lines) and `ExplorationSceneTests` pass unchanged apart from the `LeadIn`/`LeadOut` prefix. Record the solution's test count before and after (equal).
  - **Verify by hand:** start a new game with a leader whose intro has stills: black, the stills with their subtitles, skip with Confirm, black, then the warp to the map, as before.
- **Done, with deviations:**
  - **Line counts:** `EventPresenter` is 203 lines (from 285), and `StillRun` 126.
  - **What moved:** the still fields, `LeadIn`/`LeadOut`, the lead-in, skip and begin code, and the still's draw.
  - **What stayed:** `StayBlackIntoAWarp` stays in the presenter, since it owns the warp fade. It runs after a lead-out ends (as before) and after a still step leaves the run no longer running (a skip, which used to call it from inside `Skip`).
  - **Tests:** 2113 before and after; only the `LeadIn`/`LeadOut` prefix changed in `EventPresenterTests`.
