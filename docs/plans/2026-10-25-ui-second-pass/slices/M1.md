# M1. Tab icons: placeholder glyphs we draw

Part of [the UI second pass plan](../README.md). Decision 254. Design: [design.md](../design.md), "Tunables and placeholders" (tab glyphs). After M2b. Look at `docs/ui-reference/menu-tabs.webp` (an icon before each label) first.

- **M1. Tab icons: placeholder glyphs we draw** (Game, about 230 lines)
  - **Goal:** each game menu tab shows a small white icon before its label, like the reference; the icons are placeholders baked from masks in code until art exists.
  - **New types:** Game `Ui/TabGlyphShape` (internal static): the placeholder tab icons' pixels, one 12 x 12 mask per glyph, baked once by `UiTextures` and drawn at 2x (point-sampled, pixel-art crisp).
    - Glyphs, simple and readable: party (two heads), status (one figure), equipment (a sword), items (a flask), save (a book), options (a cog-like ring), system (a door). An enum `TabGlyph` lists them.
  - **Changes (Game):**
    - `Ui/UiTextures.TabGlyph(TextureLibrary, TabGlyph)`: baked on first use; BG1's warm-up list includes them.
    - `Menus/IMenuPage`: `TabGlyph Glyph { get; }`; each page returns its own; the test pages return any.
    - `Menus/GameMenuScene` (or `Menus/MenuTabsView` if M2b moved the tabs there): the glyph left of the label, the label moved right by the glyph's width plus a gap; the selected tab's slide moves both.
    - If the developer later supplies PNG icons, they replace the masks through `UiArtFiles` (out of scope).
  - **Tests** (`TabGlyphShapeTests`):
    - `Pixels_EachGlyph_AreTwelveByTwelve`
    - `Pixels_EachGlyph_HasSomeOpaquePixels`
    - `Pixels_EachGlyph_DiffersFromTheOthers`
  - **Verify by hand:** each tab shows its glyph on one column, crisp at 2x, white on the dark tab and on the blue selected one; the slide and the menu's entrance move glyph and label together. F12, compare with `menu-tabs.webp`.
