# S0. A debug key saves the screen as a PNG

Part of [the UI second pass plan](../README.md). Design: [design.md](../design.md), "Tunables and placeholders" (capture key), "Key decisions" (the capture is the host's).

- **S0. A debug key saves the 1920 x 1080 screen as a PNG outside the repo; the developer captures today's screens** (Game, about 110 lines)
  - **Goal:** in a Debug build, F12 saves the virtual screen (`JrpgGame._virtualScreen`, the 1920 x 1080 render target, whatever the window's size) as a PNG in `%USERPROFILE%\Pictures\jrpg-captures\`. Every look slice reads these captures for its spec and its hand check.
  - **New types:** Game `Hosting/CaptureFiles` (internal sealed): the next capture file's path, never overwriting one.
    - Takes the folder; `string NextPath(DateTime stamp)` gives `capture-<yyyyMMdd-HHmmss>-<n>.png`, `n` rising while a file of that name exists. The stamp is the host's wall clock, like the save stamp in `Program` (only for a file name).
  - **Changes (Game):**
    - `JrpgGame`: under `#if DEBUG`, F12 read straight from the keyboard in the host (not an `InputBindings` game button: it's a developer tool, not a game action). The press is remembered in `Update`; `Draw`, after the virtual screen is drawn and before it is shown, saves it with `RenderTarget2D.SaveAsPng` and writes the path to `DeveloperLog`. The folder is created on first use.
    - `CLAUDE.md`'s "Run game" line, or `docs/map.md`'s root line: "Debug: F12 saves a capture to `Pictures\jrpg-captures`" (ask before editing CLAUDE.md; map.md otherwise).
  - **Tests** (`CaptureFilesTests`, in a temporary folder):
    - `NextPath_EmptyFolder_EndsWithOne`
    - `NextPath_FileOfThatNameExists_TakesTheNextNumber`
  - **Verify by hand, then capture today's screens:** F12 in a 1280 x 720 window still saves 1920 x 1080. Then capture, once, the screens the plan restyles, before any look slice: title (each entry selected once), leader choice and its yes/no, the map with the dialogue box and the interaction prompt, the innkeeper's message, every menu page (Party, Status, Equipment and its choice, Items with a description and a notice, Save and its yes/no, Options, System), a battle (commands, a skill list, aiming, an action name, damage numbers), victory, defeat. Keep them in a `before` subfolder; slices name them by screen.
