# C2. Dialog buttons move into `Ui/DialogButtonView`

Part of [the escape menu third pass plan](../README.md). Decision 268. Design: [design.md](../design.md), "Replacement mapping". Right before PD1, whose OK button is the yes/no prompt's.

- **C2. Dialog buttons: `ConfirmPromptView`'s button drawing moves to `Ui/DialogButtonView`** (Game, mechanical, about 80 lines)
  - **Goal:** one drawer for a dialog's button, so the notice dialog's OK and the prompt's Yes and No are the same button. Nothing on screen changes.
  - **New types:** Game `Ui/DialogButtonView` (internal sealed): draws one dialog button: selected in the shared look with the pointer, or faintly outlined; its label centered.
    - `DialogButtonView(UiTextures ui, SpriteFontBase font)`; `public const int Width = 260`, `Height = 50` (from `ConfirmPromptView`).
    - `Draw(SpriteBatch batch, TextureLibrary textures, Button button, float opacity)`; `Button(Rectangle Area, MeasuredText Label, bool IsSelected)` (was the private `PromptButton`).
  - **Changes (Game):** `Ui/ConfirmPromptView`: `DrawButton`, `PromptButton` and the button size constants go; it draws Yes and No through `DialogButtonView`, still measuring their labels with its button font, which it hands to the view.
  - **Tests:** none new (draw-only). Record the test count before and after; `ConfirmPromptTests` pass unchanged.
  - **Verify by hand:** F12 on System's "Title Screen" prompt before and after: identical.
