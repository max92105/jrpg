# G2. Fixed-stat gear for the new slots

Part of [the stats and gear slots plan](../README.md). Decisions 270 (fixed-stat items, no rolls), 298 (the off-hand: a shield), 305, 308 (the gear comes from the starting items). Design: "Tunables" (gear bonuses). After G1c.

- **G2. Fixed-stat gear for the new slots, in the new game's starting items** (content + tests, about 110 lines)
  - **Goal:** `items.json` has an item for every new kind: wooden shield (off-hand), leather cap (head), leather gloves (hands), leather boots (feet), amber amulet, and three rings (power, sage, swift), with the design's placeholder bonuses, **each at least 5** (review edit: with percents shown as whole numbers, a smaller bonus might not move a shown value), and today's icons (`Armor.png`, exact case). The new game starts with one of each (decision 308), so they can be tried before the loot plan.
  - **Changes:**
    - `content/items.json`: eight items, each `maxStack` 99, `isUsableFromMenu` false, a one-line description naming what it gives.
    - `content/new-game.json`: the eight in the starting items.
  - **Tests:**
    - `ContentCatalogLoaderTests: Load_RepositoryItems_HaveAPieceOfEveryKind` (asserts each `EquipmentKind` has at least one item, not the count)
    - `ContentCatalogLoaderTests: Load_RepositoryGear_EveryBonusAtLeastFive` (the content rule this slice sets, over the items that have bonuses)
    - `GameSessionTests: StartNew_RepositoryContent_StartsWithAPowerRing` (asserts the entry it needs)
  - **Call sites:** Game or Data tests that assert the new game's starting inventory: grep `StartingItems` and `new-game` in tests and fix any total (the rule says entries, not totals).
  - **Verify by hand:** a new game: the inventory's Armor tab shows the eight; equip both rings on one member (one of each kind fills both ring slots), the shield and the boots; the Status page's Power, speed, dodge and resistances each move by a visible amount; save, quit, load: everything is still worn.
