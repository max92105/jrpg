# ADR 0030: Loot rolls

Part of [the loot plan](../README.md). Before D1. Decisions 339, 340, 343, 344, 349, 359. Builds on ADR 0026 (rolls draw only when uncertain; permille) and ADR 0019 (numbers in content).

- [ ] **Write ADR 0030** from the README's "ADRs" entry, option A (the developer chose it when approving the plan, so there is nothing left to ask), with B, C and D as the alternatives.
  - **Records (A):**
    - `Items/Rarity` is a closed list (decision 339); `rules.json` `loot.rarities` gives each rolled tier (Common, Magic, Rare) a weight and an affix count range (Rare 2-3, decision 340). Unique is reserved and never rolls.
    - `affixes.json` is the affix pool: an id, a stat kind, a whole-number range, the equipment kinds it rolls on, a weight. A piece never rolls one affix twice; a pool too small for the count gives what it has (decision 359).
    - `drop-tables.json` holds tables; an enemy names one (`dropTableId`), several may share it; each entry rolls on its own (decision 343).
    - Loot rolls in `GameSession.FinishBattle`, after the experience, with the session's `IRandom`; chances go through `ChanceRolls` and weighted choices through `WeightedPick`, both drawing only when uncertain. The drops return beside the rewards (`Session/BattleSpoils`), so `Battle` knows nothing of loot.
    - Only dropped gear rolls (decision 344).
    - Lifesteal, armor penetration, block and drop luck are stat kinds that only affixes give (decision 294; the affix stats plan); drop luck raises drop chances and the weights above Common (decision 349).
  - **Consequences:** no battle's draws change; a new rarity is an enum member, a rules row, a color and a name; a new affix on an existing stat is one content line.
  - Add its line to `docs/decisions/README.md`.
