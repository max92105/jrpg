# G1b-1. The inventory holds gear as a list of pieces

Part of [the loot plan](../README.md). ADR 0029, decision 345. Design: "Gear pieces" (inventory). After G1a. G1b split in two on 2026-10-27.

- **G1b-1. The inventory holds gear as a list of pieces** (Core + tests, about 200 lines)
  - **Goal:** owned gear leaves the stacks for a list of pieces in pickup order. `PartyEquipment` keeps its item-taking API for one more slice and moves plain pieces underneath.
  - **Changes:**
    - `Items/Inventory`: `Gear` (`IReadOnlyList<GearPiece>`); `Add(ItemDefinition, quantity)` adds that many plain pieces for equipment and returns 0; `AddGear(GearPiece)`; `TryRemoveGear(GearPiece)` removes the first equal piece; `GearCountOf(itemId)` counts a base's pieces. `QuantityOf`, `TryRemove` and `HasRoomFor` stay stacks-only (their docs say so).
    - `Party/PartyEquipment` (interim, gone in G1b-2): takes `GearPiece.Plain(item)` out with `TryRemoveGear`, puts the replaced piece back with `AddGear`; `OwnedFor` reads the bases of `Gear`.
    - `Session/GameSession.Capture` writes `Entries` only.
  - **Known gaps until S1a and G1c:** a save made on this commit or the next loses owned gear (worn gear is still kept by id; the count-by-id bridge was dropped on 2026-10-27, so S1a follows G1b-2 at once); the Inventory page's Weapons and Armor tabs show nothing until G1c.
  - **Tests:**
    - `InventoryTests: Add_Equipment_AddsOnePlainPiecePerCopy`
    - `InventoryTests: TryRemoveGear_EqualPiece_RemovesOne`
    - `InventoryTests: TryRemoveGear_NoEqualPiece_ReturnsFalse`
    - `InventoryTests: TryRemoveGear_RolledPiece_LeavesThePlainOne` (from R1)
    - `InventoryTests: GearCountOf_TwoSwordPieces_IsTwo`
    - `InventoryTests: QuantityOf_EquipmentBase_IsZero` (the stacks-only side)
  - **Call sites:** `QuantityOf` on an equipment id about 25 test lines (`PartyEquipmentTests` 9, `PartyEquipmentTakeTests` 4, `PartyEquipmentSlotTests` 2, `EquipmentPageTests` about 7, `GameSession*Tests` about 3) become `GearCountOf`. Write the exact count in the Done note.
  - **Backlog** (the one place this is stated): equipment's `maxStack` is no longer read; drop it from equipment entries and the validator's rule for them.
- **Done, with deviations:**
  - **Two interim bridges** (each a few lines, gone in S1a and G1c): `GameSession.Capture` saves owned gear as a count per base id, which loads back as plain pieces, because the test sessions with the whole party (`StartMapScenarios.StartWithWholeParty`) go through a save and lost their gear; `InventoryList` shows owned gear as a count per base after the stacks, so the Weapons and Armor tabs aren't empty until G1c.
  - **Pulled forward from G1b-2:** `OwnedFor` lost its catalog parameter (unused once it reads `Gear`; `SlotChoice` and `EquipmentPage` lost theirs too), and `PartyEquipment` lost its room checks, which can't trigger once gear has no stack. The six room-refusal tests left with them: `PartyEquipmentTests.TryEquip_ReplacedItemStackFull_ReturnsFalseAndChangesNothing` and `TryUnequip_InventoryStackFull_ReturnsFalseAndKeepsItem` (replaced by `TryUnequip_ManyPiecesOwned_PutsPieceBack`), `PartyEquipmentTakeTests.TryTakeFrom_NoRoomForReceiversItem_ChangesNothing`, and `EquipmentPageTests.Update_RemoveAllWithWeaponStackFull_KeepsTheWeaponWorn`, `Update_ChooseIronSwordWithBronzeStackFull_RefusesAndSaysWhy`, `Update_TakeWithNoRoomForOwnItem_ShowsTheNoRoomNotice`. `SlotChoice`'s no-room refusal stays, never firing, until G1b-2 removes it with the page's notice.
  - `OwnedFor` lists each base once (`Distinct`) and `EquipmentChoiceView` counts with `GearCountOf`, so the Equipment choice looks as before until G1b-2.
  - The new tests are in `InventoryGearTests`, not `InventoryTests` (the stacks). 23 `QuantityOf` sites on gear became `GearCountOf`; `InventoryPageTests.Constructor_StartingItems_ShowsAllInPickupOrder` became `…ShowsStacksThenGearInPickupOrder`. Tests 2598 → 2601 (6 left, 9 added: the review asked for `GameSessionGearTests.CaptureThenRestore_OwnedGear_ComesBackAsPlainPieces` and `PartyEquipmentTests.OwnedFor_TwoPiecesOfOneSword_ListsItOnce`).
