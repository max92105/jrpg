# B2. Boss phases in Core: HP thresholds switch the actions, reported as an event

Part of [the enemy skills and bosses plan](../README.md). After B1. Design: [design.md](../design.md), "Core changes", "Key decisions" 4. Questions Q6, Q7 (placeholders until answered).

- **B2. Boss phases in Core** (Core, about 230 lines)
  - **Goal:** an enemy may list phases, each with an HP threshold and its own actions. At the end of each action, before the outcome, every standing enemy whose HP has fallen below a phase's threshold enters the deepest such phase, reported as `EnemyPhaseEntered`; from then on its tactics choose from that phase's actions. A phase is never left (Q7). No content has phases until B3, so the Game never meets the event before its playback case exists.
  - **New types:**
    - `Core/Tactics/EnemyPhase`: the actions an enemy switches to below a share of its HP. `public sealed record`; `required int BelowHpPercent { get; init; }`, `required IReadOnlyList<EnemyAction> Tactics { get; init; }`.
    - `Core/Battle/EnemyPhaseEntered`: the event. `public sealed record EnemyPhaseEntered(Combatant Enemy, EnemyPhase Phase) : BattleEvent`.
    - `Core/Battle/EnemyPhases`: enters the phases standing enemies' HP has reached. `internal static`; `void EnterReached(IReadOnlyList<Combatant> combatants, List<BattleEvent> events)`. The deepest phase whose threshold the HP is below (`hp × 100 < max × percent`), only when deeper than the current one, so a big hit past two thresholds enters the second at once with one event.
  - **Changes:**
    - `Battle/EnemyDefinition`: `IReadOnlyList<EnemyPhase> Phases { get; init; } = []` (in descending threshold order, which Data checks in B3); `NamesSkill` also reads the phases' actions.
    - `Battle/Combatant`: `public EnemyPhase? EnemyPhase { get; internal set; }` (null before any; battle only, never saved).
    - `Battle/TurnFlow`: `EnemyPhases.EnterReached(combatants, events)` before each of the three `OutcomeOf` calls (end of turn, kept turn, the stunned loop); its summary names the phase step.
    - `Battle/EnemyTactics`: the current actions are `actor.EnemyPhase?.Tactics ?? enemy.Tactics`.
    - Test builder: `EnemyDefinitionBuilder.WithPhases(params EnemyPhase[] phases)`.
  - **Tests** (new file `EnemyPhaseTests`):
    - `Execute_HitTakesBossBelowThreshold_ReportsPhaseEntered` (after the hit's `EffectApplied`, before the next turn)
    - `Execute_HitLeavesBossAtTheThreshold_EntersNoPhase` (HP exactly 50 of 100: strict "below"; the rule's other side)
    - `Execute_HitPastTwoThresholds_EntersTheDeeperOnceWithOneEvent`
    - `Execute_BossAlreadyInThePhase_ReportsNothingMore` (a second hit under the threshold)
    - `Execute_BossHealedAboveThreshold_StaysInThePhase` (latched, Q7)
    - `Execute_PoisonTickTakesBossBelow_EntersThePhase` (the upkeep path)
    - `Execute_BossFalls_EntersNoPhase` (a fallen enemy enters nothing)
    - `Execute_QuickSkillHitsBossBelow_EntersThePhase` (the kept-turn path)
    - `ChooseCommand_BossInAPhase_PicksFromThePhasesActions` (phase 1 only attacks, phase 2 only a skill)
    - `Knows_SkillNamedOnlyByAPhase_IsTrue`
  - **Verify by hand:** nothing changes in play (no content has phases yet).
  - **Watch:** `TurnFlow` 86 (+6); `Combatant` 87 (+3). A new `BattleEvent` with no Game case: allowed only because no content produces it before B3 (plan lessons).
