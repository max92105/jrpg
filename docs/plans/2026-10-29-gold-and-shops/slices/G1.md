# G1. The party's purse

Part of [the gold and shops plan](../README.md). Design: [design.md](../design.md), "Core changes", README "Planner's picks" (`Purse.MaxGold`, one overflow rule).

- **G1. The party's purse** (Core, about 130 lines)
  - **Goal:** the party owns gold: a purse on `PartyState`, never below 0 nor above `Purse.MaxGold`; gold past the cap is lost (one rule for battles and sales). Nothing earns, spends or saves it yet: G2 lands the save shape right after, before G3 makes gold appear in play (the loot retro).
  - **New types:**
    - `Core/Party/Purse`: public sealed class; the party's gold, within 0 and `MaxGold`. `public const int MaxGold = 9_999_999` (seven digits fit every gold field); `int Gold`; `int Add(int amount)` (returns what was lost past the cap; throws on a negative amount); `bool CanSpend(int amount)`; `bool TrySpend(int amount)` (false, nothing taken, when short; throws on a negative amount).
  - **Changes:**
    - `Party/PartyState.Purse { get; } = new()`; its summary names the gold.
  - **Tests** (`PurseTests`, new file):
    - `Add_WithinMax_RaisesGold`
    - `Add_PastMax_KeepsMaxAndReturnsWhatWasLost`
    - `Add_Negative_Throws`
    - `TrySpend_Enough_TakesIt`
    - `TrySpend_MoreThanOwned_ReturnsFalseAndKeepsGold`
    - `TrySpend_Negative_Throws`
    - `CanSpend_ExactlyOwned_IsTrue` (the bound)
  - **Call sites:** none (`PartyState`'s constructor is unchanged).
  - **Verify by hand:** none (Core only).
- **Done, with deviations:** `Add` and `TrySpend` throw `ArgumentOutOfRangeException` (the .NET guard `ThrowIfNegative`) rather than `ArgumentException`. `CanSpend` guards a negative amount too, so the two agree (review). Added `CanSpend_OneMoreThanOwned_IsFalse`, `CanSpend_Negative_Throws` and `Add_ExactlyToMax_LosesNothing` (the bounds' other sides). Tests 2908 → 2918.
