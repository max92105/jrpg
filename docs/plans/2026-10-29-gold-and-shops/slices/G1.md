# G1. The party's purse, kept by saves

Part of [the gold and shops plan](../README.md). ADR 0022 (a format change bumps `formatVersion` and refuses older saves). Design: [design.md](../design.md), "Core changes", "Risks" (save format).

- **G1. The party's purse, kept by saves (format 6)** (Core + Data, about 210 lines)
  - **Goal:** the party owns gold: a purse on `PartyState`, never below 0 nor above `Purse.MaxGold`, that saves keep. Nothing earns or spends it yet (G2, I1, S1): the save shape lands once, before gold appears in play (the loot retro).
  - **New types:**
    - `Core/Party/Purse`: public sealed class; the party's gold, within 0 and `MaxGold`. `public const int MaxGold = 9_999_999`; `int Gold`; `bool HasRoomFor(int amount)`; `int Add(int amount)` (returns what didn't fit; throws on a negative amount); `bool CanSpend(int amount)`; `bool TrySpend(int amount)` (false, nothing taken, when short).
  - **Changes:**
    - `Party/PartyState.Purse { get; } = new()`; its summary names the gold.
    - `Saving/SaveGame.Gold` (required int); `Session/GameSession.Capture` writes `Party.Purse.Gold`; `Restore` adds `save.Gold` to the new party's purse.
    - `Data/Saving/SaveFile.CurrentFormatVersion = 6`; `FileSaveStore` refuses a gold below 0 or above `Purse.MaxGold` as unreadable, beside its null-entry check.
    - Test fixtures: `Gold = …` in the 4 `SaveGame` initializers (`SaveGameFixtures` (2), `SaveGameRepairWornTests`, `SaveGameRepairGearTests`).
