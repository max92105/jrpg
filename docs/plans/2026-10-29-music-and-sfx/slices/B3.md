# B3. Every skill names its sound

Part of [the music and sound effects plan](../README.md). After B2. Decision 423. Design: [design.md](../design.md), "Core changes", "Tunables" (skill sounds), "Risks" (skill content fixtures, cross-plan order).

- **B3. Every skill names its sound, checked at load and startup, played as its action starts** (Core + Data + Game + content, about 190 lines; adds no view type)
  - **Goal:** each skill in `skills.json` names a `soundFile` in `content/audio/effects/`; loading refuses a skill without one, and startup refuses a named file missing by exact name, naming the file and the skill. In battle a skill's sound plays as its action starts (the banner, before the impact's sounds, which still play: decision 423 gives both). Today's 23 skills share three placeholders by what they do (design.md's table); enemies' skills, when the enemy plan adds them, name theirs too.
  - **Changes:**
    - Core `Skills/SkillDefinition.SoundFile` (`string`, init, default `""`; doc: the file in the effects folder played as the skill's action starts; content always names one). The default keeps every test that builds a skill unchanged.
    - Data `Skills/SkillCatalogValidator.FindProblem`: `"soundFile must name a sound."` when it is blank, checked last so other fixtures still fail for their own problem.
    - Data `Audio/AudioReferenceCheck`: every skill's sound (`Named by skill '<id>'`), in id order, through C1's shared loop; the summary lists them.
    - Game `Battle/BattleSounds`: `ActionStarted` with a skill gives `skill.SoundFile` at the action's start, skipped when empty (test catalogs).
    - Content: `"soundFile"` on each skill in `skills.json` after `iconFile`; `content/audio/effects/PlaceholderSkillStrike.wav`, `PlaceholderSkillMend.wav`, `PlaceholderSkillCharm.wav`.
  - **Tests:**
    - `SkillCatalogValidatorTests`: `Validate_BlankSoundFile_NamesTheSkill`; its skill helper gains a sound file (budget about 5 sites).
    - `AudioReferenceCheckTests`: `FindProblems_SkillSoundMissing_NamesTheSkill`, `FindProblems_SkillSoundInOtherCase_NamesTheMismatch`
    - `BattleSoundsTests`: `Of_SkillUsed_IsItsOwnSoundAtTheStart`, `Of_SkillWithoutASound_IsSilent` (a test skill with the default)
    - `ContentCatalogLoaderSkillSoundTests` (new: `ContentCatalogLoaderTests` is 272): `Load_RepositorySkills_EveryOneNamesASound` (asserts the skills the tests need, e.g. `fire_blast` and `heal`, not a total)
  - **Verify by hand:** in a battle, Fire Blast sounds as its name shows, then its hit; Heal sounds its own, then the heal sound. Blank one skill's `soundFile`: the error screen names the skill and the field; restore it.
