# C2. An encounter's own theme

Part of [the music and sound effects plan](../README.md). After P3, and after the enemy plan's C1 (the Goblin Chief's encounter, its first user; enemy plan decision 414): if that slice hasn't landed, this one waits. Decision 420. Design: [design.md](../design.md), "Core changes", "Key decisions" 2, "Risks" (cross-plan order).

- **C2. An encounter's own theme: the Goblin Chief's boss theme** (Core + Data + Game + content, about 110 lines; adds no view type)
  - **Goal:** an encounter in `encounters.json` may name its own `musicFile`, played instead of the battle theme from its flash; it must exist in `content/audio/music/` by exact name, or the game doesn't start. The Goblin Chief's encounter names the boss theme (decision 420). Like a map's track, it is released when it leaves the mix (not a kept theme).
  - **Changes:**
    - Core `Battle/EncounterDefinition.MusicFile` (`string?`, init; doc: the encounter's own theme, a boss's; null for the battle theme). No `AbsentWhenNullFilter` entry: nothing writes encounters.
    - Data `Audio/AudioReferenceCheck`: encounter themes (`Named by encounter '<id>'`), in id order, through C1's shared loop; the summary lists them.
    - Game `Flow/MusicSelection`: a pending encounter gives `encounter.MusicFile ?? UiSoundFiles.Music.Battle`.
    - Content: `encounters.json` `goblin_chief` `"musicFile": "PlaceholderBoss.wav"`; `content/audio/music/PlaceholderBoss.wav` (C1's script, whole cycles).
  - **Tests:**
    - `AudioReferenceCheckTests`: `FindProblems_EncounterThemeMissing_NamesTheEncounter`
    - `MusicSelectionTests`: `TrackFor_EncounterWithItsOwnTheme_IsThatTheme` (a test encounter, not the repository's)
    - The enemy plan's `RepositoryEncounterTests`: `GoblinChief_NamesTheBossTheme`
  - **Verify by hand:** add `goblin_chief` to the forest's encounter table locally (as the enemy plan's C1 does), fight it: the boss theme cuts in at the flash, the forest track resumes after; a goblin fight still plays the battle theme. Revert the table.
