# S1. The effect path and the title's cues

Part of [the music and sound effects plan](../README.md). After P2 (the host's audio pass) and C2 (the ids and files). Design: [design.md](../design.md), "Key decisions" 1, 3 and 4.

- **S1. The effect path, and the title screen's move, confirm and cancel cues** (Game, about 230 lines; adds no view type)
  - **Goal:** a scene reports the effect ids its update asks for; after the update the flow writes them into the effect channel by file, each once; the host plays them at the Effects volume. The title screen is the first caller: Up and Down play `menuMove` when the selection changes, Confirm on an entry `menuConfirm`, and in the file list Cancel `menuCancel` (Q7) and a move `menuMove`.
  - **New types:**
    - `Audio/EffectChannel`: the sound effects to play after this update, by file in the effects folder, each once. `Played` (`IReadOnlyList<string>`), `Play(string file)` (a file already in it is skipped), `Clear()`. A fixed-capacity list, cleared, never reallocated.
    - `Audio/SoundEffectPlayer(SoundLibrary sounds)`: plays each file of the `EffectChannel` once on the device. `Play(EffectChannel effects, float gain)`; a silent gain plays nothing.
    - `Ui/AskedSounds`: the effect ids one update of a scene or page asks for, cleared as the next starts. `Ids` (`IReadOnlyList<string>`), `Ask(string id)` (once per id), `AskAll(IReadOnlyList<string> ids)`, `Clear()`, `AskMoveIfChanged(int selectedBefore, int selectedAfter)` (`menuMove` when they differ).
  - **Changes:**
    - `Scenes/IScene.Sounds` (default interface member, `=> []`): the effect ids, from Data's `SoundEffectIds`, the scene's last update asks for; scenes that make none keep the default (the test fakes too).
    - `Scenes/SceneStack.TopSounds`: the top scene's `Sounds`, empty with no scene.
    - `Audio/AudioChannels.Effects` (`EffectChannel`).
    - `Flow/AudioCues.Follow`: clears `Effects`, then writes each id of `scenes.TopSounds` by `definition.EffectFiles` (an id the definition lacks is reported once through `DeveloperLog` and skipped: test catalogs are silent); the summary names the effects.
    - `JrpgGame`: `_effectPlayer` built in `StartAudio`; `Update`: `_effectPlayer?.Play(_audio.Effects, VolumeLevel.GainOf(_settings.EffectsVolume))`.
    - `Title/TitleScene` (`Sounds` from an `AskedSounds`, cleared at the start of `Update`; the menu's selection compared before and after `_menu.Update`; Confirm's chosen entry asks `menuConfirm`); `Saving/SaveFilesPanel` (107) the same for its list, Confirm and Cancel, read by `TitleScene` through `AskAll` (the System page's Save and Load share the panel, S3).
  - **Tests:**
    - `EffectChannelTests` (new): `Play_SameFileTwice_KeepsItOnce`, `Clear_AfterPlays_IsEmpty`
    - `AudioCuesEffectTests` (new): `Follow_TopSceneAsksAnId_WritesItsFile` (with `TestAudio.Definition`, a new test helper mapping each id to a file named as the id), `Follow_IdTheContentLacks_SkipsIt`, `Follow_NextUpdate_ClearsTheLastEffects`
    - `TitleSceneSoundTests` (new; `TitleSceneTests` is 132): `Update_Down_AsksMenuMove`, `Update_NoInput_AsksNothing`, `Update_Confirm_AsksMenuConfirm`, `Update_CancelInTheFileList_AsksMenuCancel`, `Update_AfterASoundingUpdate_AsksNothingNew`
  - **Verify by hand:** on the title, Up and Down tick, Confirm on Load sounds, Cancel back sounds lower; Options' Effects at 0 silences them. The cues play once per press, not twice.
