# V1. Volumes in the Options page

Part of [the music and sound effects plan](../README.md). First slice. Decisions 415, 424. Design: [design.md](../design.md), "Tunables", "Key decisions" 8.

- **V1. Music, Effects and Voices volumes in the Options page; the voice-over follows its volume** (Game + text, about 200 lines; adds no view type)
  - **Goal:** the Options page lists Full screen, Text speed, Music, Effects and Voices; Left and Right step a volume between 0 and 10, stopping at either end, and the voice-over is heard at the Voices volume at once (even mid-line). Music and Effects change values nothing plays yet (P2, S1). Kept for this run only, as the other options, until the settings plan (decision 415). The values show as numbers here; V2 draws them as pips (decision 424).
  - **New types:**
    - `Hosting/VolumeLevel` (internal static): a volume setting's eleven steps read as a gain. `public const int Max = 10`; `public static float GainOf(int level)`: `(level / 10)²`, the placeholder squared taper; throws `ArgumentOutOfRangeException` below 0 or above `Max`.
  - **Changes:**
    - `Hosting/PlayerSettings`: `MusicVolume` (7), `EffectsVolume` (8), `VoiceVolume` (10), `int` levels with `{ get; set; }`; the summary names who reads them (the host's players) and keeps "for this run only (question 89)".
    - `Menus/OptionsPage` (162, about +30): rows `MusicRow`, `EffectsRow`, `VoicesRow`, `RowCount = 5`; `Change(step)` becomes a switch on the row (full screen flips; text speed and volumes step and clamp at their ends; a private `Stepped(int level, int step)` keeps the complexity down); `ValueOf(row)` reads each volume's text from a `MeasuredText[] _levels` built once for 0..10 (no per-frame formatting).
    - `Audio/VoicePlayer.Follow(VoiceChannel voice, float gain)`: sets `_playing.Volume = gain` on every call, so a change is heard mid-line; the summary says so.
    - `JrpgGame.Update`: `_voicePlayer?.Follow(_voice, VolumeLevel.GainOf(_settings.VoiceVolume))`.
    - `content/text/ui.json` + `Ui/MessageIds`: `OptionsMusicVolume` ("Music"), `OptionsEffectsVolume` ("Sound effects"), `OptionsVoiceVolume` ("Voices"); the MessageIds test covers them.
  - **Tests:**
    - `VolumeLevelTests` (new): `GainOf_Max_IsOne`, `GainOf_Zero_IsSilent`, `GainOf_Five_IsAQuarter` (pins the taper), `GainOf_AboveMax_Throws`, `GainOf_BelowZero_Throws`
    - `OptionsPageTests` (107 lines): `Update_RightOnMusic_RaisesItOneStep`, `Update_LeftOnEffectsAtZero_StaysAtZero`, `Update_RightOnVoicesAtMax_StaysAtMax`, `Update_DownFromTextSpeed_SelectsMusic` (rows picked by what they are, not by press counts)
    - Existing `OptionsPageTests` that rely on the row count (a wrap from the last row): re-checked; budget 2 fixes.
  - **Verify by hand:** start a new game as a leader with an intro, set Voices to 3 in the menu, then start a new game again: the voice-over is quieter; 0 is silent. Options shows five rows, each value framed by its diamonds when selected.
  - **Done, with deviations:** as planned, with `OptionsPage.SelectedRow` and internal row constants as the seam that picks rows by what they are; `Update_LeftOnEffects_LowersItOneStep` and `Update_LeftOnVoices_LowersIt` added so each volume's arm is tested.
