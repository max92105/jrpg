# O1. Re-skin an object

Builds on decision 449 and design.md, "Key decisions" 9.

## Goal
With an object chosen in the Objects panel and a rectangle of cells chosen in the Tiles panel, Objects > "Replace cells of the chosen object" gives the object the rectangle's picture and size as one undo step, keeping its id, category, collision outline and above-player zones, so every placement and every event naming it (the chest's give and swap, the door's swap and warp) is untouched. Cells not yet tiles become tiles first, as New object does. An NPC object (a field sprite, no tiles) can't be re-skinned this way.

## New types
- `Editor/Objects/ObjectReskin`: an object with its cells replaced by a sheet rectangle, keeping its id, category, outline and zones (in the object's own 0-1 coordinates, so they stretch with a new size).
- `Editor/Objects/ObjectReskinning`: the menu entry's view model: whether the chosen object and the chosen cells can be combined, and the replacement as one `CatalogDraft.SetObject` step (cells made tiles first). Built with the `CatalogDraft`, the Objects browser and the Tiles browser; `MainViewModel` holds it as `Reskinning` (two lines, paid by X1's freed lines).

## Changes
- `Editor/Shell/MainWindow.xaml` (and `MainWindow.ObjectEditing.cs` if the menu's handler lives there): the Objects menu entry, enabled while `Reskinning.CanReskin`.

## Verify by hand
- Choose `chest` in the Objects panel and one chest cell in an imported Mana Seed sheet, Objects > Replace cells: every chest on the start map shows the new art; interact with it in the game: it still gives the potion and opens (once `chest_opened` is re-skinned too). Ctrl+Z restores the old picture. The entry is visible in the Objects menu.
