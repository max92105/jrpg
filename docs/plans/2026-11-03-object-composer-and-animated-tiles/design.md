## Design overview

### What exists
- **Objects are made from one rectangle.** Shift + drag in the Tiles panel sets `TileBrowserViewModel.SelectedCells` (a `SheetCellRectangle`); Objects > New object from selection (`MainWindow.ObjectEditing.OnNewObjectClicked`) opens `NewObjectWindow` over `MainViewModel.StartNewObject()` (`NewObjectViewModel`: id and category with `IdProblem` through `ObjectIds.ProblemOf`, `CategoryProblem`), and `MainViewModel.CreateObject` makes the cells tiles (`CatalogDraft.TileIdsOf(SheetCellRectangle)`, `TileAt ?? AddTile`, outside the history, decision 113), builds the object (`ObjectFromCells.Build`) and adds it as one step (`AddAndChoose`: `CatalogDraft.SetObject`, chosen in the Objects panel, Objects mode); the shell then opens the Shapes window (decision 124). `ObjectReskinning` (Objects > Replace cells, decision 449) gives the chosen object the marked cells through `ObjectReskin.Reskin` (`original with { Width, Height, Tiles }`), refusing an NPC and a sheet whose image is missing.
- **The object format** (`Core/Maps/ObjectDefinition`, `ObjectTile(X, Y, TileId)`): one tile per cell at most (`ObjectCatalogValidator`: "an object has one tile per cell"), cells may be empty, at least one tile unless it is an NPC; outline and zones in 0..1 of the object's size.
- **The Tiles panel's sheet view** `Tiles/TileBrowserView` (view-only code-behind: subscribes to its `TileBrowserViewModel`'s `PropertyChanged` in `OnDataContextChanged` and unsubscribes when the data context changes; a click calls `SelectCellAt`, a drag `SelectCellsBetween`, or `WalkabilityMarking.FlipCellAt` while marking) over `TileBrowserViewModel` (330 lines: sheet choices, the Cut panel, `CellAt`, `SelectedCell`, `SelectedCells`, `MarkedCells`, `ChoiceText`). Its `Images` (`TileImages`) and `Marking` are set by the main window.
- **Editor drawing**: `Tiles/TileImages.TileImageOf(tileId)` crops and caches a tile by (sheet record, column, row) and returns `MissingArtMark.Picture` for a missing image or a cell past it; `Maps/MapDrawing.Draw` builds one frozen `DrawingImage` of the whole map each time the map or catalog changes, canopies being the object's tiles again under a clip; `DrawObject` makes the previews (the Objects panel's `ObjectBrowserView.Preview`, the placing ghost, the Shapes window).
- **Game drawing**: `Rendering/TileAtlas` works out each tile's `TileImage(SheetFile, Source)` once; `Exploration/MapView` (built per map in `ExplorationScene.EnterCurrentMap`) draws layers and objects through it; `Rendering/CanopyTextures` bakes every canopy once through `ObjectSpriteBaker.CanopyPixels`, which reads `TileAtlas.ImageOf`. `ExplorationScene.Update(delta, input)` is the scene's time; `SceneStack` updates only the top scene. `WalkAnimation` is the one animation, driven by the delta.
- **Content**: `tiles.json` loads straight into `TileDefinition` (ADR 0002) through `ContentCatalogLoader`, checked by `TileCatalogValidator`; `ContentWriter.WriteMapCatalogs` writes it with `ContentFileWriter`, leaving out the optional fields listed in `AbsentWhenNullFilter`; `ArtReferenceCheck.FindProblems` checks each tile's cell against its image at game startup, and `FirstTileOutside` lets `ImportTilesheetImage` refuse an image too small for the tiles cut from it. The repository's `content/tiles.json` is empty since the reset (decision 453); the test world's frozen `tiles.json` holds the old tiles.
- **Catalog edits**: `Catalogs/CatalogDraft` (294 lines) turns each change into an undo step (`Do(CatalogEdit)`); `SetObject` skips a record equal by content (`IsSameObject`).
- **The pack's animations** are Tiled tilesets: a `.tsx` file (XML) beside its PNG names the image (`<image source>`), the cut (`tilewidth`, `tileheight`, `columns`, `margin`, `spacing`) and, per animated tile, `<tile id="n"><animation><frame tileid="m" duration="ms"/>...</animation></tile>`, where a tile id is `row * columns + column`.

### Core changes
- `Core/Maps/TileAnimation` (sealed record): a tile's animation as content: how many frames run rightward from its cell and the time each shows. `FrameCount` (int), `FrameMilliseconds` (int), `MinFrames` (2), `FrameDuration` (computed, `TimeSpan`), `FrameAt(TimeSpan elapsed)` (the index shown after that time: `(elapsed.Ticks / FrameDuration.Ticks) % FrameCount`, in `long`, so years of play stay in range; `ArgumentOutOfRangeException` on a negative time).
- `Core/Maps/TileDefinition.Animation` (`TileAnimation?`, init, null by default: no constructor churn) and `ColumnShownAt(TimeSpan elapsed)` (`Column` plus the frame, `Column` for a still tile): the one place both shells read the cell drawn.

Why Core: the game and the editor both turn a time into a cell and must agree; the editor never references the Game. `FrameAt` is a formula, not state: Core still never reads a clock.

### Key decisions
1. **The composer paints sheet cells, not tiles** (decisions 456, 457, 461). A canvas cell holds a `SheetCell`; Save turns each into a tile through `CatalogDraft.TileIdsOf` (`TileAt ?? AddTile`), so a cell not yet a tile is made one, and an animated tile's own cell paints that animated tile. Editing reads each `ObjectTile` back to its tile's cell; when two tiles share a cell the lowest id comes back (`TileAt`'s rule), which only matters for hand-made content.
2. **One window for New and Edit, its rules headless** (decision 455). `CanvasPainting` owns the strokes, `ObjectComposerViewModel` the naming and the result, `ObjectComposing` the start and the apply; the window only turns mouse positions into canvas cells. `ObjectComposerViewModel.ToObject(tileIdOf)` builds a new object (`ObjectNaming`'s id and trimmed category, no outline, no zones) or `Original with { Width, Height, Tiles, Category }`, so Edit keeps the id, outline and zones (stretched in 0..1 with a new size) and every placement and event, as decision 449 does today. `ObjectComposing.TryApply` follows the dialog pattern (`Start...` returns the view model, `TryApply` refuses on a problem).
3. **The picker is the Tiles panel's view model** (decision 457). The composer shows a second `TileBrowserView` bound to `MainViewModel.Painting.Browser`; choosing a sheet or cells in the composer chooses them in the panel too. No second view model to build, and Set up and Cut work there. The window doesn't set the view's `Marking`, so a click always chooses. On `Closed` the window sets the picker's `DataContext` to null, so the view unsubscribes from the browser (its `OnDataContextChanged` already does) and the closed window isn't kept alive by the browser's event.
4. **Strokes undo inside the composer** (decision 461). `ObjectCanvas` is immutable, so `CanvasPainting` keeps a stack of canvases: a stroke (press to release) or a resize is one step. The main editor's history sees only Save.
5. **The animation is a frame count to the right of the tile's cell** (decision 463; ADR 0039). That is the shape of every animation the pack has, it needs no list (so no null entries, no cell references to check beyond the last frame against the image), and the tile's own cell stays the first frame, so the sheet view, the composer and the canopy bake are right without reading the animation. The frames are on the tile's sheet and leave with it in `RemoveTilesheet` and `SheetPurge`.
6. **One formula, two clocks** (decisions 464, 470). `TileAnimation.FrameAt(elapsed)` and `TileDefinition.ColumnShownAt(elapsed)` in Core. The game: `MapView` holds its time and `Advance(delta)`; `ExplorationScene.Update` calls it first, whatever runs (an event, an encounter's pause); a new map's view starts at zero; screens over the map stop the scene's updates, so the water stands still under the menu, the Forge and a shop. The editor: `TileAnimationTime` moves on by the rendering time `CompositionTarget.Rendering` reports (view only, in `MainWindow.TileAnimation.cs`) and raises `FramesChanged` only when some animated tile's frame index changed, so a 60 Hz tick redraws a picture at the animation's pace, not 60 times a second.
7. **No allocation per frame in the game.** `TileAtlas` keeps per tile an array of source rectangles (one for a still tile, one per frame for an animated one) and its animation; `ImageAt(tileId, elapsed)` returns a `TileImage` struct; `ImageOf(tileId)` stays, the first frame, for the canopy bake.
8. **The editor animates small pictures, not the map** (decision 466). The Objects panel's preview, the composer's canvas and the Animate panel's preview are one object or one tile each: redrawing them on `FramesChanged` is cheap. The map is one frozen drawing of thousands of cells; animating it needs shared brushes swapped per frame (the backlog line), so until then it shows the first frame. The placing ghost and the Shapes window show the first frame too (they're drawn once per choice).
9. **The Animate panel sits in the Tiles panel** (decision 467), as the Cut panel does, under the sheet the developer already sees; it takes the chosen cell, a "frames to the right" count and a time; no click routing on the sheet. Its view model lives beside the browser (`MainViewModel.Animating`), not in it: `TileBrowserViewModel` is at 330 lines.
10. **The import refuses rather than guesses** (decision 469). A `.tsx` maps to the set-up sheet whose image file name equals its `<image source>`'s file name (case ignored, as Windows does); its tile size, margin and spacing must equal the sheet's cut (else tile ids would land on other cells). An animation becomes a frame count and time only when its frames are the tile's own id then the next ids, staying on its row, all with one duration; any other shape refuses the whole file, naming the tile, so nothing is half-imported. The parse and the shape rule are Data's (`TiledTilesetReader`, a file format reader like `PngSize`); the editor matches the sheet and sets the catalog.

### Extension points
- **Several tiles per object cell** (decision 456's later plan): `ObjectCanvas` would hold a list per cell and `ObjectTile` gain a level; the format change needs an ADR.
- **The animated map** (backlog): `AnimatedTileBrushes`, one shared unfrozen `ImageBrush` per animated tile, swapped on `TileAnimationTime.FramesChanged`; `MapDrawing` paints those cells with it and leaves such a drawing unfrozen.
- **An explicit frame list or per-frame times** (ADR 0039's options): an optional `frames` list beside `frameCount`; `FrameAt` walks cumulative times; the importer then accepts any Tiled animation on one sheet.
- **Offsets per cell**: an optional flag on `TileAnimation` and a `FrameAt(elapsed, GridCell)` adding a fixed offset from the cell's position (a hash, no `IRandom`, nothing saved).
- **Animated canopies** (decision 465): bake one canopy per frame for an object holding an animated cell under a zone.
- **Animation as a map-wide time** (water moving under the menu): move the time from `MapView` to a clock on `MapArt`, advanced by the flow.

## Risks
- **Two views over one browser.** The composer's picker and the Tiles panel share `TileBrowserViewModel`: an open Cut panel shows in both, and a choice made in the composer stays in the panel after it closes (expected, and the hand check says so). Without clearing the picker's data context on `Closed`, every closed composer would stay subscribed to the browser and redraw its sheet on every change (CO5's hand check opens and closes it repeatedly).
- **The `.tsx` files are the pack's.** They're XML, not images, so reading them is outside decision 438's rule, but they stay outside the repository (decision 439) and tests write their own. If a later pack's `.tsx` uses frames on other rows, other tiles' cells or several durations, the import refuses it whole, naming the tile; the Animate panel or the explicit-frames option is then the way.
- **Canopies don't animate** (decision 465): an overlay animation is on its own layer, never in an object, so this only bites an object built with an animated cell under a zone.
- **The editor's map is still** (decision 466): the developer sees the animation in the Animate panel, the Objects panel's preview, the composer and the game, not on the map being painted.
- **Re-cutting a sheet with animated tiles** can push a last frame outside the grid: the editor draws the mark, the startup check names the tile; the re-cut's warning doesn't count frames (out of scope).
- **The frozen test world** needs no change: `animation` is optional and left out while null. Tests with an animation build their catalogs in code.
- **Determinism:** no randomness; the game's time is the delta's sum; nothing saved. **Save format:** untouched. **Performance:** the game does one dictionary lookup and one division per drawn tile, no allocation; the editor's tick compares frame indexes per distinct animation and redraws at most three small pictures when one changes.
- **File sizes:** `MainViewModel` (503) shrinks by about 40 over phase 1 before AI2, AE1 and AE2 add about 8; `CatalogDraft` (294) moves its removals out in AI2 before `SetTileAnimations`; `MainWindow.xaml.cs` (569) takes at most two lines (AE2 starts the tick); `TileBrowserViewModel` (330) changes one sentence of `ChoiceText` (CO5); `MainWindow.ObjectEditing.cs` (248) about 15 (CO5, CO6); `MapDrawing` (211) about 5 (AE3).
