# B2. Tile cells and animations past the image are refused, as counts

Data, about 70 lines. Builds on decision 542 and design.md, "Replacement mapping". Comes before R3, which works on the rest of `ArtReferenceCheck`.

## Goal
The startup art check and Import refuse a tile whose cell, or whose animation's last frame, lies past its image, whatever the numbers a hand-edited `tiles.json` holds. Today both checks add pixels and columns in `int`:
- `IsCellInside` sums `sheet.CellLeft(column) + sheet.TileWidth`, which wraps for a column near 2^28 (16-pixel cells), so a far-off still tile passes;
- `LastFrameColumn` adds the column and the frame count, which wraps negative from column 2 with `frameCount = int.MaxValue`, so the animation passes and `TileAtlas` throws at startup.

## Files
- `src/Jrpg.Data/Art/ArtReferenceCheck.cs` (196 → about 200):
  - `IsCellInside(column, row, sheet, size)` becomes a count check: `column < sheet.ColumnsIn(size.Width) && row < sheet.RowsIn(size.Height)` (column and row are never negative: the tile validator refuses it). `CellLeft` and `CellTop` leave the check; for every in-range value the result is the same, since `ColumnsIn` counts the whole cells the width holds.
  - The animation check becomes `IsLastFrameInside(tile, sheet, size)`: `frameCount <= sheet.ColumnsIn(size.Width) - tile.Column`, a still tile counting one frame (the code-quality rule: `count > limit - start`, never `start + count > limit`). Its two callers, `AddTilesOutside`' animation branch and `FirstTileOutside`, read it.
  - `LastFrameColumn` stays only for the message, worked out in `long` (`tile.Column + (long)frameCount - 1`), so the text is unchanged.
- New `tests/Jrpg.Data.Tests/Art/ArtReferenceCheckBoundTests.cs` (about 60): the three tests, on the test world's forest sheet (512 x 384 px in 16 px cells) as `ArtReferenceCheckAnimationTests` sets it up. `ArtReferenceCheckTests` (279) takes nothing new (the 250-line sibling rule).
- `docs/plans/backlog.md`: delete the AE1 line.
