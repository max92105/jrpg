# IU11. The equipment form's bonus rows

Editor, about 180 lines (view model about 60, XAML about 20, tests about 100). Needs IU10. Design: design.md, section
5.1; decisions 880, 888.

## Goal
Under an equipment's kind, its bonus rows: Add bonus adds a row with the first stat not yet listed among those a base
item may give (not `StatKinds.AffixOnly`), greyed once every one is listed; each row a stat box and a value box; Remove
bonus removes the chosen row. Two rows naming one stat, or a value that isn't a number, show on the problem line; Data's
bound comes through the list. This is how a weapon gives Power (decision 888).

## New types
- `Editor/Items/StatBonusRow` (internal sealed partial, `ObservableObject`): one bonus as typed, a stat and its value;
  `Stat`, `ValueText`, `Problem` ("Value must be a whole number (was 'x')."), `Index` for the line.

## Changes
- `Editor/Items/ItemEquipmentViewModel`: `Bonuses` (`ObservableCollection<StatBonusRow>` from the record, in `StatKind`
  order), `SelectedBonus`, `AddBonusCommand`, `RemoveBonusCommand`, `StatChoices` (every `StatKind` but the affix-only
  ones); `Problem` adds "bonuses[1] (power): Value must be a whole number (was 'x')." and "bonuses names power twice.";
  `Changed` on a row typed, added or removed (never its `Problem` notice); `ToEquipment` builds `StatBonuses` from the
  rows.
- `Editor/Items/ItemCatalogPage.xaml`: the rows as a `ListBox` whose rows hold a stat combo and a value box, a row
  chosen by a `PreviewGotKeyboardFocus` EventSetter (never an `IsKeyboardFocusWithin` trigger, which loses the choice to
  the buttons), Add bonus and Remove bonus beside it; the value boxes on `PropertyChanged`.
