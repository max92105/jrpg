## Goal
Database > Affixes opens the Affixes page in `CatalogDialog`: every affix in id order, the ones added this session
after; Add, Duplicate, and Remove (only an affix added this session); the chosen one's Id, Stat, Min, Max, Weight, Gold
value and "Rolls on" with a box per equipment kind. The problem line (the dialog's) is the chosen affix's own first,
then any affix's by id (`RecordListProblem`), then Data's message for the pool (`CatalogProblems.OfAffixes`); a unique's
values don't depend on the ranges (decision 866), so narrowing a range touches no unique. OK is one undo step,
`CatalogDraft.SetAffixes`, which also re-resolves every unique's fixed affixes from the new pool, so a stat changed on
an affix reaches the uniques naming it; an undo restores both.

## New types
- `Editor/Loot/AffixCatalogViewModel` (internal sealed partial, `ObservableObject`): every affix as the page lists,
  adds and removes them, and the problem line; implements `Workspaces/IEditedCatalog`: `Problem` (raised on every typed
  change), `ChosenKey` (the chosen affix's id; null with none or while a new one has no id), `Choose(string key)`;
  `Affixes`, `SelectedAffix`, `AddAffixCommand`, `DuplicateCommand`, `RemoveAffixCommand`, `ToAffixes()` (throws on a
  problem).
- `Editor/Loot/AffixEditingViewModel` (internal sealed): `Start()` from `catalog.Current`, `Apply(edited)` through
  `SetAffixes`; declares `ICatalogEditing<AffixCatalogViewModel>` if the mode bar's WS2 has landed.
- `Editor/Loot/AffixCatalogPage.xaml(.cs)` (a `UserControl`): the page (design.md, 5.2) on the recipe's step 3: boxes
  on `PropertyChanged`, `AncestorType=loot:AffixCatalogPage`, resources from `EditorTheme.xaml` only, the kind boxes in
  two columns of four, sizes from `double` constants.
