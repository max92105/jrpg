# T2. `rules.json` names the damage tiers and an effect names one by id

Data + content, about 240 lines (about 140 of them tests). Needs T1. Design: design.md, sections 2.4 and 2.5
("References resolve at load").

## Goal
`rules.json` lists `damageTiers` (the sheet's five); a skill's or item's effect may write `"tier": "low"` and loads
with the `DamageTier` record in `Effect.Tier`. An unknown tier stops the load naming the file, the path and the id.
Data refuses a tier on anything but damage or a heal, a power beside a tier, and a tier on an item. No skill names a
tier yet (T4).

## New types
- `Data/Content/CatalogReferenceConverter<T>` (internal sealed, `JsonConverter<T>` where `T : class`): reads a content
  id as the record it names from a catalog already loaded, and writes a record back as its id.
  - `CatalogReferenceConverter(IReadOnlyDictionary<string, T> records, Func<T, string> idOf, string recordName)`.
  - `Read`: a JSON string naming a key, else `JsonException("no {recordName} '{id}'.")`; a non-string token,
    `JsonException("a {recordName} is named by its id, a string.")`.
  - `Write`: `writer.WriteStringValue(idOf(value))` (row 7's writer is its first production caller; tested here).

## Changes
- `Core/Content/GameRules`: init `IReadOnlyList<DamageTier> DamageTiers { get; init; } = []` ("decision 704's tiers,
  `rules.json` `damageTiers`"). Test rules built elsewhere keep the empty default.
- `Data/Content/ContentJsonOptions`: `public static JsonSerializerOptions StrictWith(params JsonConverter[] converters)`:
  a copy of `Strict` with the converters added, made read-only.
- `Data/Content/ContentFileReader`: `Read<T>(string path, JsonSerializerOptions options)`; the one-argument `Read`
  passes `Strict`.
- `Data/Content/ContentCatalogLoader.Load`: `rules.json` is read first; `skills.json` and `items.json` read with
  `StrictWith(new CatalogReferenceConverter<DamageTier>(tiersById, tier => tier.Id, "damage tier"))`;
  `ReadValidated` gains the options overload. The crafting check's comment ("rules.json is read before the items")
  stays true.
- `Data/Content/GameRulesValidator`: `damageTiers`: no null entry, an id not empty and not listed twice, `perPower` at
  least 1 (`"damageTiers: 'low' perPower must be at least 1 (was 0)."`).
- `Data/Effects/EffectValidator`: `FindTierProblem`: a tier only on `damage` or `restoreHp`
  (`"effect.tier is only for a damage or restoreHp effect (was low on grantStatus)."`); a tiered effect's power must be
  0 (`"effect.power must be 0 beside a tier, which sets the amount (was 15)."`, decision 792). Keeps
  `FindProblem` a chain under CA1502.
- `Data/Items/ItemCatalogValidator`: an item's effect names no tier (`"effect.tier is for skills: an item isn't raised
  by its user (decision 785)."`).
- `content/rules.json`: `"damageTiers": [ { "id": "low", "perPower": 2 }, { "id": "medium", "perPower": 4 },
  { "id": "high", "perPower": 9 }, { "id": "massive", "perPower": 22 }, { "id": "extreme", "perPower": 58 } ]`.
