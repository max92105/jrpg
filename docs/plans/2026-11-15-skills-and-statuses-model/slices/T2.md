# T2. `effects.json` holds the tiered records and an effect names one by id

Data + content, about 270 lines (about 160 of them tests), plus about 60 lines of `effects.json`. Needs T1. Design:
design.md, sections 2.4, 2.5 ("References resolve at load") and 3.1 (the records).

## Goal
`content/effects.json` holds the 11 records T4 needs (`blunt_1`, `blunt_2`, `dark_1`, `dark_3`, `fire_1`, `fire_2`,
`heal_1`, `heal_2`, `light_2`, `piercing_2`, `slashing_1`), in the writer's layout, each `perPower` the sheet's number
for its suffix. A skill's or item's effect may write `"tier": "fire_1"` and loads with the record in `Effect.Tier`. An
unknown id stops the load naming the file, the path and the id. Data refuses a bad record, a tiered effect on anything
but damage or a heal, a kind or damage type differing from the record's, a power beside a record, and a tiered effect
on an item. No skill names a record yet (T4).

## New types
- `Data/Content/CatalogReferenceConverter<T>` (internal sealed, `JsonConverter<T>` where `T : class`): reads a content
  id as the record it names from a catalog already loaded, and writes a record back as its id.
  - `CatalogReferenceConverter(IReadOnlyDictionary<string, T> records, Func<T, string> idOf, string recordName)`.
  - `Read`: a JSON string naming a key, else `JsonException("no {recordName} '{id}'.")`; a non-string token,
    `JsonException("a {recordName} is named by its id, a string.")`.
  - `Write`: `writer.WriteStringValue(idOf(value))` (row 7's writer is its first production caller; tested here).
- `Data/Effects/EffectCatalogValidator` (internal static): `effects.json`'s rules.
  - `Validate(string fileName, IReadOnlyList<TieredEffect> effects)` over `ContentListValidator` (ids, "effect").
  - `FindProblem`: kind `damage` or `restoreHp` (`"kind must be damage or restoreHp (was revive)."`); a damage record
    has a `damageType`, a heal record none; `perPower` from 1 to 1000 (decision 818;
    `"perPower must be within 1..1000 (was 0)."`).

## Changes
- `Core/Content/ContentCatalog`: `IReadOnlyDictionary<string, TieredEffect> TieredEffects { get; init; }`, empty by
  default as `EffectStrips` is: "the tiered effects a skill's damage or heal names, by id (ADR 0056)".
- `Data/Content/ContentJsonOptions`: `public static JsonSerializerOptions StrictWith(params JsonConverter[] converters)`:
  a copy of `Strict` with the converters added, made read-only.
- `Data/Content/ContentFileReader`: `Read<T>(string path, JsonSerializerOptions options)`; the one-argument `Read`
  passes `Strict`.
- `Data/Content/ContentCatalogLoader.Load`: `internal const string EffectsFile = "effects.json"`, read and validated
  first; `skills.json` and `items.json` read with `StrictWith(new CatalogReferenceConverter<TieredEffect>(effectsById,
  effect => effect.Id, "effect"))`; `ReadValidated` gains the options overload; `TieredEffects` set on the catalog.
- `Data/Content/AbsentWhenNullFilter`: `(typeof(TieredEffect), "damageType")` ("ADR 0056: a heal record has no type.").
- `Data/Effects/EffectValidator`: `FindTierProblem` in the `??` chain after `FindDamageTypeProblem`: a tiered effect
  only on `damage` or `restoreHp` (`"effect.tier is only for a damage or restoreHp effect (was fire_1 on
  grantStatus)."`); the effect's kind and damage type equal the record's (`"effect.kind is restoreHp but fire_1 is
  damage."`, `"effect.damageType is ice but fire_1 is fire."`); its power 0 (`"effect.power must be 0 beside a tiered
  effect, which sets the amount (was 15)."`, decision 792).
- `Data/Items/ItemCatalogValidator.FindProblem`: an item's effect names no tiered effect (`"effect.tier is for skills:
  an item isn't raised by its user (decision 785)."`), checked before SE1's `OwnEffectStripValidator`, which the
  `Validate` chain runs after `FindProblem`.
- `content/effects.json`: the 11 records sorted by id, one field per line, CRLF and a final newline (the order the
  writer gives: `id`, `kind`, `perPower`, `damageType`).

## Verify by hand
- Run the game: it starts as before (the records load, nothing names one).
- Set `fire_1`'s `perPower` to 0 in `content/effects.json`, run the game: the start stops on "effects.json: effect
  'fire_1': perPower must be within 1..1000 (was 0)." (the prefix is `ContentListValidator`'s); revert.

- **Done, with deviations:** `OptionalFieldFilter` skips a type read through a converter (its type info has no
  fields there): without it the tiered effect's `damageType` filter line threw for every file read with the reference
  converter. The converter's refusal of a non-string reads "the effect must be named by its id, a string.".
  `MainViewModelTests.Constructor_BrokenContentFile_ShowsTheLoaderMessageAndNoMaps` now breaks `effects.json`, the
  file read first. The validator's rows also check the record id twice. Hand check: the game's start is the
  developer's to see; the `perPower` 0 refusal is pinned through the loader by `Load_EffectWithPerPowerZero_RefusesNamingTheRecord` (review).
