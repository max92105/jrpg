# T4. Every skill names its damage tier

Content + Data, about 170 lines of code and tests (about 110 of them tests), plus about 40 changed lines of
`skills.json` and one of `enemies.json`. Needs T3. Design: design.md, section 3.1 (the table to apply), section 7
(balance).

## Goal
Every skill in `content/skills.json` whose effect is `damage` or `restoreHp` names its tier per design.md, section 3.1,
with `"power": 0`; the Goblin Chief has `"power": 5`. Data refuses a skill's damage or heal effect without a tier, so a
new skill can't slip back to a flat power. The game plays with the new numbers; the simulations still pass.

## Changes
- `content/skills.json`: the 19 tiered effects of section 3.1 (`"tier"` added, `"power"` set to 0); the descriptions
  of `heal`, `recovery` and `heal_all` lose their HP numbers ("Restores HP to one ally.", "Restores its user's HP,
  then keeps mending them for two turns.", "Restores HP to every ally."; decision 793).
- `content/enemies.json`: `goblin_chief` gets `"power": 5` after `"damageType"` (decision 791), in the writer's layout.
- `Data/Skills/SkillCatalogValidator`: a skill whose effect is `damage` or `restoreHp` names a tier
  (`"effect.tier is required for a skill's damage or restoreHp effect: its amount is its user's Power times the tier
  (decision 704)."`); a revive or a status-only skill doesn't.
- Repository tests that pinned a skill's power, rewritten to ids and shape (never the new value):
  - `ContentCatalogLoaderTests.Load_RepositoryContent_RecoveryHealsItsUser` (it compares the whole effect with power
    30): assert `RestoreHp`, `Targeting.Self`, a tier, and the Regen grant's kind and turns as before.
  - `Jrpg.Data.Tests/TestContent/skill-without-description.json` keeps failing on its missing description (the
    serializer refuses it before the tier rule); check, no change expected.
- Game tests on repository skills (`BattleScenarios.Skills`): run `Jrpg.Game.Tests`. Known: `StatusMarksViewTests`
  bashes a 30 HP goblin with Sarxian (Power 12: Low deals 24, it survives); `BattleTurnSequenceTests` and
  `ActionWindUpTests` use Shield Bash for its stun. A test failing on a repository skill's amount is moved onto a skill
  built in the test, its reason in the Done note.
- Simulations: build, then run `tests/Jrpg.Simulations/bin/Debug/net10.0/Jrpg.Simulations.exe -showLiveOutput`;
  paste the Chief's table in the Done note. `ForestFightsSimulation` doesn't move (attack only, enemies without
  skills); `BossFightSimulation` asserts that every fight ends, the Chief uses each action and reaches its phase: if
  one fails, the reason goes in the Done note before any re-pin (decision 813).
