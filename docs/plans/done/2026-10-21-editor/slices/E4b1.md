# E4b1. Ctrl+Z undoes catalog changes

Part of [the editor plan](../README.md). Design: [design.md](../design.md), "Key decisions" 8 (one undo order) and "Risks" (undo across two histories); decision 117; ADR 0014. First catalog change to undo: E4a's blocked marks. Split from E4b at step 2 (about 470 lines with the refusal); the in-use refusal is [E4b2](E4b2.md), right after.

- **E4b1. Ctrl+Z undoes catalog changes** (Editor, about 320 lines)
  - **Goal:**
    - Ctrl+Z (and Edit > Undo, the toolbar's Undo) undoes the newest change, whether it went to the open map or to the catalogs; Ctrl+Y redoes in the same order. A blocked mark is undone like a paint stroke.
    - Catalog steps survive switching maps (the catalogs belong to no map); the closed map's steps don't (as today: a map's history is dropped when another opens).
    - A tile made by painting (E3d) is not a step of its own: undoing the paint keeps it, and the catalogs stay unsaved until Ctrl+S. A blocked tile made by a mark on a new cell is part of that mark's step: undoing the mark removes it.
    - The unsaved state follows undo: undoing back to the saved catalog clears "Unsaved changes" for the catalogs.
    - Every later catalog change (cuts, shapes, new objects, NPCs) is a step through the same path with no extra code in those slices beyond a test each.
    - **Known gap until E4b2:** an undo that removes a tile still used on a map isn't refused; the next Ctrl+S refuses to save instead, naming the map (E3c's validation).
  - **New types:**
    - `Catalogs/CatalogEdit` (record): one catalog change that can be undone and redone, as two functions from catalog to catalog, so an undo reverts only its own records and never a map saved since.
    - `Catalogs/CatalogHistory`: the undo and redo stacks of catalog edits, and whether the catalogs differ from the last save (as `EditHistory` does for a map).
    - `Shell/UndoJournal`: the order in which steps went to the open map or to the catalogs, so Undo and Redo go to the newest.
  - **Changes:**
    - `Catalogs/CatalogDraft`: `SetWalkable` and a new `AddBlockedTile(SheetCell)` (the mark on a new cell, one step) go through a private `Do(CatalogEdit)`; `Undo()`, `Redo()`, `CanUndo`, `CanRedo`; a `StepRecorded` event; `IsDirty` from the history. `AddTile` (painting) isn't a step: it clears redo and keeps the catalogs unsaved until saved.
    - `Tiles/WalkabilityMarking`: a new cell goes through `AddBlockedTile`.
    - `Maps/MapViewModel`: a `StepRecorded` event when `Do` or a finished stroke records a step.
    - `Shell/MainViewModel`: `UndoCommand` and `RedoCommand` go through the journal (ending a stroke first); the journal drops map entries when another map opens.
    - `Shell/MainWindow.xaml`: Ctrl+Z, Ctrl+Y, the toolbar and the menu bind to the main view model's commands.
  - **Tests:**
    - `CatalogHistoryTests`: `Undo_AfterOneEdit_ReturnsIt`, `Redo_AfterUndo_ReturnsTheSameEdit`, `Push_AfterUndo_ClearsRedo`.
    - `CatalogDraftTests`: `Undo_AfterSetWalkable_RestoresTheTile`, `Undo_BackToSavedVersion_IsClean`, `Undo_NothingDone_ChangesNothing`, `Undo_AddBlockedTile_RemovesTheTile`, `Undo_AfterAddTile_StaysDirty`.
    - `UndoJournalTests`: `Undo_MapStepThenCatalogStep_UndoesTheCatalogFirst`, `Undo_AfterAnotherMapOpened_SkipsTheClosedMapsSteps`, `Redo_AfterANewStep_HasNothing`.
    - `MainViewModelTests`: `Undo_BlockedTileMarkThenPaint_UndoesThePaintFirst`, `Undo_CatalogStepAfterSwitchingMaps_UndoesIt`.
  - **Verify by hand:**
    - [ ] Mark a tile blocked, paint a stroke, Ctrl+Z twice: the stroke goes, then the cross; Ctrl+Y twice brings both back.
    - [ ] Mark a tile blocked, switch maps, Ctrl+Z: the cross goes (the step survived the switch).
    - [ ] Mark then undo: "Unsaved changes" clears when nothing else is unsaved.
- **Done, with deviations:** about 450 lines with tests, above the 320 estimated (tests and doc comments). A small `Shell/UndoTarget` enum (Map, Catalogs) names the journal's entries. `CatalogHistory` holds the saved depth (as `EditHistory` does) instead of a version number in the draft; `RecordChangeOutsideHistory` (a tile made by painting) keeps the catalogs unsaved and clears redo, so redoing an undone mark can't overwrite a tile painted since with the same id. `CatalogEdit` has no name text yet: nothing shows it. `MainViewModel.cs` is now 435 lines.
- **Review fixes (2 Criticals):** a tile painted off the map dropped the catalogs' redo without the journal hearing (a phantom Ctrl+Y, then Ctrl+Z out of order): `CatalogDraft.RedoDropped` now tells the journal (`ForgetUndoneCatalogSteps`); Redo across both histories is tested (`Redo_AfterUndoingMarkAndPaint_RedoesTheMarkFirst`, `Redo_NewTilePaintedOffTheMapAfterUndo_HasNothingToRedo`). `UndoStep` renamed `UndoTarget`. Left: `Undo` and `Redo` in `MainViewModel` mirror each other; `MainViewModel` (about 440 lines) should hand the undo routing to its own type (backlog).
