# ADR 0021: Status effects

Part of [the class mechanics plan](../README.md). Design: [design.md](../design.md), "Tunables and placeholders" (Statuses), "When things happen in a turn", "Key design decisions" 2 and 3.

- **ADR 0021: Status effects** (checkbox step before ST1; write with `/adr`)
  - **Question:** what is a status (stun, taunt, guard, exposed, poison, regeneration), where do its rule and its numbers live, and when does it act?
  - **Options:**
    - A. a closed `StatusKind` list in Core, each kind's rule in code with a test, granted by an effect with a power and a number of turns from content (recommended);
    - B. statuses as content definitions (`statuses.json`). Stun, Taunt and Exposed are rules, not numbers, so B still needs code per kind;
    - C. stat modifiers only: no stun, taunt, poison or regeneration.
  - **Record with the decision:**
    - An effect may carry one `StatusGrant` (kind, power, turns), applied to each target still standing after the effect. `EffectKind.GrantStatus` grants without changing HP, with no `EffectApplied`.
    - A status counts down at the end of its holder's turns, starting from the turn after the one it was granted on (a fresh mark). A lost turn (Stun) counts.
    - Re-applying refreshes the turns and keeps the stronger power; it never stacks.
    - A fall clears the fallen's statuses; every status ends with the battle and is never saved.
    - Events: `StatusApplied`, `StatusEnded`, `TurnSkipped`, `StatusTicked`, each added with its mechanic (ADR 0004).
    - Status names are player-facing text in `ui.json` (ADR 0010).
  - **Done when:** `docs/decisions/0021-status-effects.md` is accepted and indexed.
- **Done, with deviations:** as planned. The developer accepted A on 2026-10-24.
