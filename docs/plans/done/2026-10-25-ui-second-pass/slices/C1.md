# C1. `UiTheme` in partial files by screen

Part of [the UI second pass plan](../README.md). Design: [design.md](../design.md), "Clean-up selection". Right before W1a, the first slice that adds theme colors (the sizing slices change values in place).

- **C1. `UiTheme` in partial files by screen** (Game, mechanical, about 300 lines moved, 30 new)
  - **Goal:** `Ui/UiTheme.cs` (291 lines) becomes a `partial` static class over a few files, so the look slices can add colors without crossing 300 lines. No call site changes.
  - **Changes (Game):**
    - `Ui/UiTheme.cs` keeps the shared part: text colors, sizes, bars, tabs, selection, scrims, rows, the color helpers (`Over`, `ColorFromHex`, `FromStraightArgb`).
    - `Ui/UiTheme.Battle.cs`: the battle values (vignette, top shade, battle bars, enemy bar, XP bar, reward bar, card header, bar track, text outline, turn backdrop and enemy half, status rims, aura glow, command panel fills, floating colors, banner).
    - `Ui/UiTheme.Dialogue.cs`: the message box, prompt, key cap, speaker strip, caption band.
    - `TurnEnemyHalf` reads `TurnBackdrop` at initialization: static field order across partial files isn't defined, so keep both in the same file (`UiTheme.Battle.cs`), and keep `KeyCap`'s written-out color (its comment explains why).
    - The class summary says how the files are split.
    - Remove the `UiTheme.cs` line from `docs/plans/backlog.md`.
  - **Tests:** none new; `UiThemeTests` and all others pass unchanged. Record the solution's test count before and after (equal).
  - **Verify by hand:** the title, the menu and a battle look the same as before (a quick screenshot of each, before and after).
- **Done, with deviations:**
  - **Line counts:** `UiTheme.cs` is 181 lines, `UiTheme.Battle.cs` 76 and `UiTheme.Dialogue.cs` 56. The member lines are identical before and after (checked with a sorted diff).
  - **Tests:** 2104 before and after.
  - **Comments:** the two partial files describe themselves in a plain comment, so the class keeps one doc summary. Two moved summaries were rewrapped to fit 120 columns.
