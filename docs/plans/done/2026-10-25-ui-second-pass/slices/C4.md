# C4. `StatusPage` split: `StatusSheet` and `StatusSheetView`

Part of [the UI second pass plan](../README.md). Design: [design.md](../design.md), "Replacement mapping", "Clean-up selection". The backlog's "`StatusPage` split" line.

- **C4. `StatusPage` split: `StatusSheet` and `StatusSheetView`** (Game, about 300 lines moved, 40 new)
  - **Goal:** `Menus/StatusPage` (289 lines) keeps its input, cursor and page contract; what it shows of a member and how it draws move out, so M3a can add content and M3b restyle it without crossing 300 lines. Right before M3a.
  - **New types:**
    - Game `Menus/StatusSheet` (internal sealed record): what the Status page shows of one member, built when the shown member changes.
      - `static StatusSheet Of(PartyMember member, ContentCatalog catalog, StatusLabels labels, MemberVitalBars shownVitals)` (4 parameters; today's `SheetOf`).
      - Today's `MemberSheet` fields: name, class name, portrait file, the experience texts, the stats, what the member wears. The experience bar's `(Earned, Needed)` too, so the view doesn't compute it.
      - `ToNextLevelText` and `ExperienceProgress` move here (internal static, as today).
      - The class name comes from `ContentCatalog.ClassOf` (backlog line), not `Classes[...]`.
    - Game `Menus/StatusSheetView` (internal sealed): draws a `StatusSheet`: portrait, experience, parameters, what the member wears. It owns the fonts, the section titles, the vital bars and the XP bar, and the layout constants.
    - `StatusLabels` moves from a nested record to its own file `Menus/StatusLabels` if both new types need it (they do: the sheet reads `MaxLevel` and `Empty`, the view the captions).
  - **Changes (Game):** `StatusPage` builds the sheet in `ShowMember` and calls the view in `Draw`; `ShownStats` reads `_sheet.Stats`. The equipment slot labels can come from `EquipmentSheet.Slots` and `EquipmentSheet.LabelIdOf` (backlog): do it only if it removes code.
    - Remove the "`StatusPage` split" and "`StatusPage` looks up `_catalog.Classes`" lines from `docs/plans/backlog.md`. `docs/map.md`, Menus line: `StatusSheet`/`StatusSheetView`.
  - **Tests:** none new; `StatusPageTests` pass with `StatusPage.ToNextLevelText` and `StatusPage.ExperienceProgress` read as `StatusSheet.…` (a mechanical prefix edit, 4 sites). Record the solution's test count before and after (equal).
  - **Verify by hand:** the Status page looks exactly as before for each member, Left and Right still change member, the sidebar still marks the shown one. Before/after screenshot.
- **Done, with deviations:**
  - **Line counts:** `StatusPage` is 102 lines (from 291), `StatusSheetView` 168, `StatusSheet` 60 and `StatusLabels` 19.
  - **The HP meter lives in the view** (`StatusSheetView.Vitals`): the page shows the member's vitals on it, builds the sheet from it (its HP text), then hands the sheet to the view (`Show`, which also fills the experience bar).
  - **Slot labels and what's worn come from `EquipmentSheet.Slots`** (with `EquipmentSheet.LabelIdOf` and `PartyMember.EquippedIn`), so the Status page no longer names Weapon and Armor itself; the class name comes from `ContentCatalog.ClassOf`.
  - **Tests:** 2151 before and after; only the `StatusSheet.` prefix changed (4 sites).
