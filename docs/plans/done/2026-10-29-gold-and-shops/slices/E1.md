# E1. A map event opens a shop

Part of [the gold and shops plan](../README.md). Decisions 353, 370 (no fade to black). ADR 0006 (map event flow), ADR 0008 (scenes return requests). After H1. The forge plan's E1 is the model. Design: [design.md](../design.md), "Key decisions" (one opening-step signal and one way back), "Replacement mapping", "Risks" (content written by the editor).

- **E1. The `openShop` event step opens the named shop and waits for it** (Core + Data + Game, about 230 lines; adds no view type)
  - **Goal:** an event step `openShop` names a shop from `shops.json`; it waits, like the Forge's step, while that shop's screen is open; leaving the Shop continues the event. The Forge and the Shop open and close through one transitions class. No content uses the step until N1, after the editor can show it (E2).
  - **New types:**
    - `Core/Events/OpenShopStep(string ShopId)`: public sealed record; the step that opens a shop and waits until it closes.
    - `Game/Scenes/ShopRequested(string ShopId)`: the request the map scene returns to open a shop.
    - `Game/Flow/EventScreenTransitions(SceneStack scenes, SceneFactory factory)`: opening a screen a map event asks for over the map, without a fade (it fades itself in), and closing it to go on with the event. `OpenForge(GameSession session)`, `OpenShop(GameSession session, string shopId)`, `Close(GameSession session)` (pops, then `ContinueEvent`). Replaces `ForgeTransitions`.
  - **Changes:**

    - Data: `Content/ContentTypeDiscriminators` `"openShop"`. `Maps/MapContentReferences.ShopIds` (`IReadOnlySet<string>`, an `init` member defaulting to empty: the record already has five positional members). Its five construction sites: `ContentCatalogLoader` sets it (the shops load before the maps); `ContentWriter.ContentReferencesOf` sets it (else the editor's map save refuses a map with an `openShop` step); `MapEventValidatorTests` sets it for the new test; `MapLayoutValidatorTests` and `MapFolderReaderTests` stay as they are. `MapEventValidator.FindStepProblem`: `OpenShopStep shop => FindOpenShopProblem(shop, references)` ("openShop has unknown shop id '…'"), a helper so the switch stays under CA1502.
