# S1. The effect path and the title's sounds

Part of [the music and sound effects plan](../README.md). After P2 (the host's audio pass). Decisions 421, 425. ADR 0035 (effects as values, the flow's timing). Design: [design.md](../design.md), "Key decisions" 1, 3 and 7.

- **S1. The effect path, and the title's move, confirm and cancel sounds** (Game, about 245 lines: about 140 of code, 8 tests; adds no view type)
  - **Goal:** a scene reports the effect files its update asks for; the flow clears the effect channel as its update starts and copies the top scene's files into it right after updating the scenes, before applying any request; the host plays each once at the Effects volume. The title is the first caller: Up and Down play the move sound when the selection changes, Confirm on an entry the confirm sound, and in the file list a move, a confirm on a loadable save, and Cancel the cancel sound. Confirm on an empty or damaged slot is refused and silent (no buzzer, decision 421).
  - **New types:**
    - `Audio/EffectChannel`: the sound effects to play after this update, by file in the effects folder, each once. `Played` (`IReadOnlyList<string>`), `PlayAll(IReadOnlyList<string> files)` (a file already in it is skipped), `Play(string file)`, `Clear()`. A list reused, never reallocated.
    - `Audio/SoundEffectPlayer(SoundLibrary sounds)`: plays each file of the `EffectChannel` once on the device. `Play(EffectChannel effects, float gain)`; a silent gain plays nothing; an empty file name (a test catalog's) is skipped.
    - `Ui/AskedSounds`: the effect files one update of a scene or page asks for, cleared as the next starts. `Files` (`IReadOnlyList<string>`), `Ask(string file)` (once per file), `AskAll(IReadOnlyList<string> files)`, `Clear()`, `AskMoveIfChanged(int selectedBefore, int selectedAfter)` (the move sound when they differ).
  - **New files:** `content/audio/effects/PlaceholderMenuMove.wav`, `PlaceholderMenuConfirm.wav`, `PlaceholderMenuCancel.wav` (C1's script, `-FadeMilliseconds 5`).
  - **Changes:**
    - Data `Audio/AudioFolders.Effects = "effects"`; the summary lists it.
    - `Ui/UiSoundFiles.Effects` (in `effects/`): `MenuMove`, `MenuConfirm`, `MenuCancel`; `UiSoundFilesTests` gains the group (theory row and the group count).
    - `Scenes/IScene.Sounds` (default interface member, `=> []`): the effect files the scene's last update asks for. Its summary states the rule: the flow reads the top scene's right after its update, before applying the request it returned, so a sound asked in the update that opens the menu or the Forge, or starts a fade, is played once; a scene that makes none keeps the default (the test fakes too).
    - `Scenes/SceneStack.TopSounds`: the top scene's `Sounds`, empty with no scene.
    - `Audio/AudioChannels.Effects` (`EffectChannel`).
    - `Flow/GameFlow.Update` (about +3): `Audio.Effects.Clear()` first; `Audio.Effects.PlayAll(_scenes.TopSounds)` right after `_scenes.Update`, before `Start(request)` or the fade's hold.
    - `JrpgGame`: `_effectPlayer` built in `StartAudio`; `Update`: `_effectPlayer?.Play(_audio.Effects, VolumeLevel.GainOf(_settings.EffectsVolume))`.
    - `Title/TitleScene` (an `AskedSounds` cleared as `Update` starts; the menu's selection compared around `_menu.Update`; the chosen entry asks the confirm sound; `Sounds` overrides the default). `Saving/SaveFilesPanel` (107) gets its own `AskedSounds` for its list, Confirm on a loadable file and Cancel, exposed as `Sounds` and added by `TitleScene` (`AskAll`); the System page's Save and Load (S3) and the defeat screen (S2) share it.
  - **Tests:**
    - `EffectChannelTests` (new): `PlayAll_SameFileTwice_KeepsItOnce` (the clearing is the flow test's below)
    - `GameFlowSoundTests` (new: `GameFlowTests` is 321): `Update_TitleConfirmsNewGame_PlaysTheConfirmSound` (the request goes behind the fade, the sound still plays, once), `Update_AfterASoundingUpdate_ChannelIsEmpty`
    - `TitleSceneSoundTests` (new; `TitleSceneTests` is 132): `Update_Down_AsksTheMoveSound`, `Update_Confirm_AsksTheConfirmSound`, `Update_CancelInTheFileList_AsksTheCancelSound`, `Update_ConfirmOnAnEmptySlot_AsksNothing`, `Update_ConfirmOnADamagedSlot_AsksNothing`
  - **Verify by hand:** on the title, Up and Down tick, Confirm on Load sounds, Cancel back sounds lower, an empty slot is silent; Options' Effects at 0 (from a game's menu) silences them. Each press sounds once.
  - **Done, with deviations:** as planned, with `SaveFilesPanel.Update` clearing and asking the move, and `ChooseToLoad` adding the confirm only when a save really loaded, so a file damaged since the list opened is silent too; a Continue whose file broke is silent as well. Cancel is asked by the panel's host, since the panel never reads that button. Not heard (unattended loop): the hand check is yours. Tests 3491 → 3508.
