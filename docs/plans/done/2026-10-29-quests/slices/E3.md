# E3. The quest condition's boxes in both event dialogs

Part of [the quests plan](../README.md). After E2. Design: [design.md](../design.md), "Key decisions" (three boxes). (The Quest giver preset this file held before is deferred: README, "Out of scope".)

- **E3. The quest, condition and stage boxes in both event dialogs** (Editor, about 110 lines)
  - **Goal:** beside the leader condition, the object and cell event dialogs show a Quest box ("(none)" and the quest ids), a condition box (not started, active, at stage, reached stage, completed; enabled once a quest is chosen) and a stage box (shown for the two stage kinds), bound to the event's `QuestGate`; the dialog's problem line shows the gate's problem and OK waits for it.
  - **New types:** none.
  - **Changes:**
    - `EventListViewModel.QuestChoices` and `CellEventViewModel.QuestChoices` (`["", .. choices.QuestIds]`, as `LeaderChoices`); `ConditionKinds` (the enum's values in its order, with their labels).
    - `ObjectEventsWindow.xaml` and `CellEventWindow.xaml`: the three boxes beside the leader box, styled `BasedOn` the theme (`.claude/rules/editor.md`).
  - **Tests:**
    - `CellEventViewModelTests: QuestChoices_StartWithNone`
    - `EventListViewModelQuestTests: QuestChoices_ListTheCatalogsQuestsInIdOrder`
    - `EventListViewModelQuestTests: TryApply_GateWithoutStage_RefusedWithTheGatesProblem`
  - **Watch:** a combo whose list lacks the event's quest (removed from content) clears it, as the leader combo does; the map save would refuse the old one anyway (QV).
  - **Verify by hand:** give an NPC two Talk events, the first "placeholder_errand, not started", the second with no quest; choose "reached stage" with no stage: OK refuses and says why; pick a stage; save and reopen: both conditions are kept and the summaries say them; Ctrl+Z undoes the change. The same three boxes in a cell's dialog.

- **Done, with deviations:** the stage box is enabled only for the two stage kinds rather than hidden (the windows have no visibility converter, and a hidden box would shift the row); the kind box is `QuestConditionKindChoice.All` (kind and label) bound by `SelectedValuePath`. The condition's problem reaches OK through the lists' existing `Problem` chain, tested on the list ("Event villager_0, Choose the stage..."). Not captured (unattended loop): the hand check is yours.
