# J1. The quest journal

Part of [the quests plan](../README.md). After SV (it reads `QuestLog.Progress`, the start order). Decisions 390 (main before side), 391 (active newest first). Design: [design.md](../design.md), "Structure and folder dependencies" (`Quests` stays a leaf). Kept apart from G1 and G2: folding it in would take either past 250 lines; its `Completed` list arrives with its first user, G3.

- **J1. The quest journal: the active quests in Core's order** (Core, about 100 lines)
  - **Goal:** Core says which active quests the page lists and in which order, with the stage each is at; the page (G1) only formats it.
  - **New types:**
    - `Core/Quests/QuestJournal` (public sealed class, internal constructor over the `QuestLog`): the log as the player reads it. `Active` (`IReadOnlyList<QuestEntry>`, built when read: the page reads it on opening, never per frame): main quests before side quests, each newest first.
    - `Core/Quests/QuestEntry` (public sealed record): one quest in the journal: its `Quest` (`QuestDefinition`) and the `Stage` (`QuestStage`) it is at.
  - **Changes:** `Core/Session/GameSession.Quests` (`QuestJournal`, built once in the constructor over `_context.World.Quests`).
  - **Tests** (`QuestJournalTests`):
    - `Active_MainAndSideQuests_MainFirst`
    - `Active_TwoSideQuests_NewestFirst`
    - `Active_CompletedQuest_NotListed`
    - `Active_AdvancedQuest_EntryAtTheCurrentStage`
    - `GameSessionTests: Quests_NewGame_NoActiveQuest`
  - **Verify by hand:** nothing to see yet; G1 shows it.

- **Done, with deviations:** the journal reads the log through a new `QuestLog.StartedQuests` (the definitions in start order) with `StageOf` and `IsCompleted`, rather than a log entry type; `Active` reverses that order, drops the completed and sorts main before side (a stable sort keeps newest first in each).
